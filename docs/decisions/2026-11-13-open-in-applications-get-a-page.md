# 2026-11-13: Open in… applications get a page in Settings, with a repository to try them on

**Asked (Björn, on PR #2479, from v3.2.9-ux9 on Windows):** "I found out that the open in... popup where you can add an application is broken. Maybe make it open a page inside the settings? I think that's the proper fit for it anyways, no? Make it possible to select a repo for testing however still, that's a good feature." And, the same day: "fix the Open on Gitea thing in the ... part of the app. It opens inside the tauri shell... make it open in the browser. also, instead there, make it appear on Open in..."

## What was broken

- **The dialog, from a Repositories row.** *Add an application* was drawn where its *Open in…* stood. On Code's Repositories list that is a row's fading action group (`.tf-rowacts`), which is moved into place with `transform: translateY(-50%)`, and a transformed ancestor is the box a `position: fixed` element fills instead of the window. So the dialog's scrim was the group's 95 × 65 px, the dialog stood beside the row running off the bottom of the window, a click on most of it reached the table under it, and once the pointer left the row (and focus wasn't on a text field) the group faded out with the dialog in it. Reproduced on `1f84766e` (v3.2.9-ux9) and on the head, in headless Chrome on the fake fixture and on the windowless backend over a saved database; the repository header, a commit and Settings drew it whole. WebView2 lays out `transform` as Chrome does. *Clone*'s *Where should clones go?* on the same row had the same fault.
- **Windows in what the dialog drew.** *It will run* and *Started …* read a Windows checkout wrong: `{name}` was the whole path (split on `/` only), a file was joined with `/` onto a backslash path, a pull request's worktree likewise, and a path with a space was shown in single quotes, which a Windows command line doesn't take. What ran was right: the backend joins with `Path` and passes each argument whole. Pinned in `openin.test.ts`, failing before.
- **Open on Gitea.** A file's *More* (⋯) drew *Open on <source>* as a plain link, so the WebView went to Gitea itself, with no way back. *The rest on the source*, a cut file's source link and an item page's *Open in <source>* (`target="_blank"`, a bare WebView window on Windows) were the same.

## The ruling

- **The page.** Settings › Checkouts and Open in › *Add an application* (`#/settings/checkouts/add`) or the application's name (`…/app/<id>`), each optionally followed by the repository and the object to try (`…/<repo>/<kind>/<value>`). Every *Open in…* ends with *Add an application* (this repository, this object) and *Manage applications* (the section). Settings' table has *Edit*, *↑* and *Add an application*; the *Applications for Open in* dialog is gone, its default radio being *Make default* and its *↑* the table's. *Save*, *Cancel* and *Remove* go back where the page was opened from, as `Esc` and *Back to* do; `Esc` with no opener goes up to the section.
- **Everything the dialog did stays**: name, a command per object, placeholders as buttons, the warnings, *Remove* with *Undo*, the whole list written on save.
- **It will run, per command.** Each command's line is drawn under it, split as the backend splits it and filled from **Try it on**: a repository with a checkout on this disk (the one the page came from, else the last tried, else the first found), then a file, a commit (a range is that commit and the one before it) or a pull request of it, each offered only once its command is typed. With no checkout anywhere the section says so and how to get one (*Clone*, *Clone all…*). The reads are the app's own (Code's list and checkouts, *Go to file*, Commits, Pull requests, a pull request's header): no IPC was added.
- **Only a saved template runs (ADR-0016, #1643), and a try is taken back.** *Try it* saves the draft and runs it by the id the save gave it, as before. Leaving the page without *Save*, by *Cancel*, `Esc`, *Back*, a nav press or any other address, takes the try back: only that entry, put back as it was before the first try or gone if it was new, so a default made elsewhere meanwhile stays (the dialog put the whole list back). What was typed stays for the session and comes back with the page; *Cancel* drops it.
- **A double press acts once.** *Try it* holds its row's press while it saves and starts and for the press hold after; ↑ holds the column for a second, since the row moves and a second press under a still pointer lands on the row that took its place.
- **A dialog fills the window wherever it was opened.** `TfDialog` moves its scrim up to its page when an ancestor would hold a `position: fixed` (a transform, a filter, containment). Anywhere else it stays where it was drawn.
- **A web page opens in the browser, never in the window.** *Browser* is on every *Open in…* (the repository's and the file's now, as the code objects' already), named as the code objects' entry was, through `openExternal` (http and https only) with a toast when it refuses. *Open on <source>* left *More*. The links the app draws to a source's page call `openLink`, and `installExternalLinks` sends any other press on a link to another origin to the browser.
- **Not the Tauri side's `on_navigation`.** On macOS wry calls it for every frame's navigation, iframes included, so refusing an off-origin address there would also refuse Docs' embeds and a renderer's frame. The document's guard covers what the page draws; a window-level net would need wry to tell a frame from the top.

## Tested

- Vitest: `TfAppPage.test.svelte.ts` (the page, the picker, the try and its take-back, *Remove*), `app-page.test.ts` (the address, Settings' and the route's rules, the take-back), `openin.test.ts` (Windows; failing before), `TfDialog.test.svelte.ts` (the scrim under a transform; failing before), `external-links.test.ts`, `TfOpenIn.test.svelte.ts` (*Browser* opens the file's page and the window stays; failing before), `TfOpenObject.test.svelte.ts`, `TfCheckoutsSection.test.svelte.ts`, and the desktop witness drivers' landings in `App.test.svelte.ts`.
- Press trips (`--strict`): every press the page brought, twice by key, twice with the pointer still, and left during its toast; `app-page`, from *Open in…* to the page, tried on a picked repository, saved and back with it in the menu.
- The windowless backend over a clone of the saved database, with a clones root under a path with a space: the page fills from it, *Try it* saves and reports what the program said, and *Save* returns to the repository.

## Reversing it

Put `TfAppDialog.svelte` and `TfAppsManage.svelte` back from before PR #2479's commit 488dd109 and have `TfOpenIn` open them; the page, its address and the table's links can stay. The dialog's lift in `TfDialog`, the Windows preview and the browser links are fixes that stand on their own.
