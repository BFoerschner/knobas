# Domain docs

This repo is single-context: one glossary, `CONTEXT.md` at the root, and one ADR directory, `docs/adr/`.

- Read `CONTEXT.md` before exploring, and the ADRs that touch the area you work in.
- Use the glossary's terms in issue titles, test names and proposals. Do not drift to synonyms it avoids. A concept the glossary lacks is either language the project does not use or a gap to note for `/domain-modeling`.
- If your output contradicts an ADR, say so explicitly ("Contradicts ADR-0007 because ...") rather than silently overriding it.
