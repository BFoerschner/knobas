# knobas M1 — Stream E (Search & Launcher) Implementation Plan

> **For agentic workers:** Execute via the **PR loop** in `2026-08-24-knobas-roadmap.md` §3: one `implementer` agent (Opus 5, high) per task in its own worktree/branch → PR → `pr-reviewer` agent (Opus 5, xhigh) → iterate (max 3 rounds) → squash-merge on approval + green `just check`. Steps use checkbox (`- [ ]`) syntax for tracking. Tasks 1–7 are backend and strictly ordered; Task 8 (IPC) needs 4, 6, 7; Task 9 (UI) needs 8; Task 10 (bench) needs 4, 6, 7. Tasks 1+2 may ship as one PR (they are two halves of the parser's input surface, ~250 lines together); everything else is one PR per task.

**Goal:** The `⌘K` box of spec §4: one query grammar (prefixes, source aliases, inline `key:value`), one backend parser, one dynamic-SQL builder over the synced corpus, results grouped by kind in a fixed order with monogram, sync-age provenance and structured snippet highlighting, built-in smart lists with counts and change badges, an empty-query board — and a measured proof that all of it answers in **< 100 ms over ≥ 100 k items**.

**Architecture:** A new crate `crates/knobas-search` (ruling **P9**) owns everything: the grammar parser (pure, no sqlx), the vocabulary it parses against (loaded from `knobas.source_config`), **one** module that assembles dynamic SQL (`sql.rs`, the only place `AssertSqlSafe` may appear — roadmap §4 gotcha 2), the grouping/snippet layer, the hand-written built-in smart lists, and the launcher board. `crates/knobas-app/src/commands/search.rs` is a thin shim; `app/src/lib/ipc/search.ts` is its hand-written mirror; `app/src/lib/launcher/**` is the Svelte surface. The corpus in M1 is `sync.live_item` (migration 0002) and nothing else — but the builder is written over a `Corpus` description so M4's asset corpus (with ancestor `path_text`) joins as a second `union all` branch without touching the parser, the grouping, the commands or the UI (spec §4 "asset search matches ancestor path names"). Task 5 proves that seam with a real second corpus.

**Tech Stack:** Rust (edition 2024, toolchain ≥ 1.94), sqlx 0.9 (runtime-checked queries only), PostgreSQL 18.6 FTS (`websearch_to_tsquery`, `ts_rank_cd`, `ts_headline`), Tauri 2.11, Svelte 5 + Vite, criterion for the bench.

**Spec:** `docs/superpowers/specs/2026-08-23-knobas-design.md` §4 (the launcher box — this stream implements it), §3a (extensibility: search knows `sync.item`, never adapter names), §2 (the top strip's `⌘K`, entity addressing), §14 (performance: local search < 100 ms for ~100 k items).
**Contract:** `docs/superpowers/plans/2026-08-24-m1-interfaces.md` §1 (migration 0002 — consumed, never edited), §2.4 (the four commands and every DTO — reproduced verbatim, not redesigned), §6.1 (ownership), §6.3 (E's exit criteria), §8 (rulings P1, P2, P9, P13).
**Carry-overs:** `docs/superpowers/plans/2026-08-24-m1-carryovers.md` — stream D's "structured snippet highlighting (sentinel selectors → segments); M0 ships plain text over title+body" is discharged here (Task 4), because the snippet is produced by search, not by the shell.

## Global Constraints

Inherited from plan-01 and still binding:

- Postgres runs on **TCP 127.0.0.1**; never Unix sockets (macOS 103-byte socket-path limit).
- **Runtime-checked queries only** (`sqlx::query`, `query_as` + `FromRow`) — no `query!` macros, no compile-time `DATABASE_URL`, no offline cache. This is not negotiable for this stream in particular: its main query is assembled at runtime and `query!` cannot express it.
- Every generated FTS column is `GENERATED ALWAYS AS (...) STORED` — roadmap §4 gotcha 1, verbatim: *"PG 18: `GENERATED ALWAYS AS (...)` without `STORED` silently creates an unindexable virtual column — always write `STORED`."* (Binding here for the M4 corpus design in Task 5, which must not sketch a virtual column.)
- Entity ids are strings `"<namespace>:<key>"`; the kind lives in `knobas.entity.kind` / `sync.item.kind`, never in the id.
- Commit style: short imperative subject, no attribution footer. Task-branch commits are unsigned; signing is disabled **per-worktree only** (`git config extensions.worktreeConfig true`, then `git config --worktree commit.gpgsign false`) — never write `commit.gpgsign` to the shared repo config.
- Quality gate: `just check` = `cargo fmt --all --check` + `npm run check && npm run build` in `app/` + `cargo clippy --workspace --all-targets -- -D warnings` + `cargo clippy --workspace --lib -- -D warnings` + `cargo test --workspace`. Every task ends with it green.

M1 additions binding this stream:

- Roadmap §4 gotcha 2, verbatim: *"sqlx 0.9: dynamic SQL needs `AssertSqlSafe`; keep it in one reviewed query-builder module. Never bind `tsquery` — bind text into `websearch_to_tsquery('english', $1)`, compute the tsquery once as a FROM item. Never map `tsvector` to `String`."* → `AssertSqlSafe` appears in `crates/knobas-search/src/sql.rs` and **nowhere else in the workspace**; Task 3 ships a test that fails if it does.

`src/query.rs` shape (write it in this order — leading prefix, then tokens):

```rust
/// Longest-first so `assets:` is not read as `asset` + a stray `s:`.
const LEADING: &[(&str, Prefix)] = &[
    (">", Prefix::Action), ("?", Prefix::Help),
    ("note:", Prefix::Note), ("list:", Prefix::List),
    ("assets:", Prefix::Asset), ("asset:", Prefix::Asset),
];

pub fn parse(raw: &str, vocab: &Vocabulary) -> Parsed {
    let mut p = Parsed::default();
    let head = raw.trim_start();
    let rest = match leading_prefix(head) {              // `t ` handled inside
        Some((marker, prefix)) => { p.query.prefix = Some(prefix); &head[marker.len()..] }
        None => head,
    };
    match p.query.prefix {
        Some(Prefix::Note)  => p.query.filters.kinds.push("note".into()),
        Some(Prefix::Asset) => p.query.filters.kinds.push("asset".into()),
        Some(Prefix::List)  => { p.list_id = Some(rest.trim().to_lowercase()); return p; }
        _ => {}
    }
    let mut terms: Vec<String> = Vec::new();
    for token in tokenize(rest) { … }                    // the table below
    p.query.text = terms.join(" ");
    p.prefix_last_term = !raw.ends_with(char::is_whitespace)
        && !p.query.text.is_empty()
        && terms.last().is_some_and(|t| !t.starts_with('"'));
    p
}
```

Token table (each row is one `if let` arm, in this order):

| token | effect | `prefix` if unset |
|---|---|---|
| `/x` | `sources += vocab.resolve_source("x")`; empty ⇒ `unknown_tokens += "/x"` | `Source` |
| `@me` | `mine = true` | `Person` |
| `@x` | `authors += x` (**E-Q1**; until it is granted: `unknown_tokens += "@x"`, no predicate) | `Person` |
| `#x` | `kinds += "ticket"`; `x` (if non-empty) becomes a term | `Ticket` |
| `k:v` where `k ∈ {source, src, in}` | as `/v` | `Source` |
| `k:v` where `k ∈ {kind, type}` and `v` names a kind in the catalog | `kinds += v` | — |
| `k:v` where `k = updated` | `today→1`, `yesterday→2`, `week→7`, `Nd→N`, `Nw→7N`, `Nm→30N`, else unknown | — |
| `k:v` where `k ∈ {is}` | `mine` for `v = mine`, else unknown | — |
| `k:v` where `k ∈ {author, owner, by}` | as `@v` | `Person` |
| `k:v` where `k ∈ {env, health, type}` (unmatched `type`) | `unknown_tokens += token` — the estate's keys, M4 | — |
| anything else | a search term, verbatim (quotes included) | — |

`tokenize` splits on whitespace but keeps a double-quoted run together **with its quotes**, so `websearch_to_tsquery` still sees the phrase. Deduplicate `sources`/`kinds` while preserving first-seen order (a stable order keeps generated SQL and tests deterministic). Cap `unknown_tokens` at 8 entries — it is display material, and an adversarial paste should not make the response unbounded.

`merge` implements the table in the test: per dimension, "the text wins if it spoke", `mine` ORs, and `authors = if mine { vocab.identity } else { [] } ∪ parsed.authors`.

- [ ] **Step 3: Implement**

- `load` is one query, and it must stay one query: it runs on the hot path of every search.
  ```sql
  select id, kind as adapter_kind, display_name, config ->> 'username' as username
    from knobas.source_config
   where enabled
   order by id
  ```
  (`kind` is 0001's column name for the adapter kind; interfaces §2.2 calls the DTO field `adapter_kind`. Do not rename the column — that is a migration, and 0002 did not.)
- `identity`: the distinct non-empty usernames, sorted — the array `mine` binds.
- Built-in alias table (spec §4 "source aliases `/ji` `/gt` `/tc` `/cf` `/nt` `/as`"), mapping alias → **adapter kind**: `ji|jira → jira`, `gt|git|gitea → gitea`, `tc|ci|teamcity → teamcity`, `cf|conf|wiki|confluence → confluence`, `nt|note|notes|local → note`, `as|asset|assets|infra|kuma|flowrun → asset`. Resolution order in `resolve_source`: exact configured id → alias → adapter kind → unique case-insensitive prefix of a configured id or display name → nothing. Aliases whose adapter is not configured resolve to nothing (and the token is reported), which is honest: `/cf` in M1 means "a Confluence you have not added".

Declared metadata always wins.
- `SearchError` (in `lib.rs`): `Db(#[from] sqlx::Error)`, `UnknownList(String)`, `Invalid(String)`.

The generated shape, for one corpus with text (comments belong in the code — a reviewer must be able to see why each stage exists):

```sql
with q as (
  -- Computed once, as a FROM item, and never bound as a tsquery (gotcha 2).
  -- The ':*' variant is what makes the box answer while the word is still
  -- being typed: `websearch_to_tsquery` output is already a well-formed,
  -- quoted tsquery, so appending ':*' to its *text* and casting back turns
  -- only the last lexeme into a prefix. The CASE guards the empty case,
  -- where ':*' alone would be a syntax error.
  select case
           when websearch_to_tsquery('english', $1)::text = '' then null::tsquery
           when $2 then (websearch_to_tsquery('english', $1)::text || ':*')::tsquery
           else websearch_to_tsquery('english', $1)
         end as tsq
),
m as materialized (
  -- Deliberately narrow: entity_id, kind, rank, updated_at and nothing else.
  -- This CTE holds one row per *match*, which for a common word is thousands;
  -- carrying titles and bodies through it is what turns a 20 ms search into a
  -- 200 ms one. MATERIALIZED because it is read twice below and the scan must
  -- happen once.
  select i.entity_id, i.kind, ts_rank_cd(i.fts, q.tsq) as rank, i.item_updated_at
    from sync.live_item i cross join q
   where i.fts @@ q.tsq
     and i.source_id = any($3)                       -- only when filtered
     and i.kind = any($4)
     and i.item_updated_at >= now() - make_interval(days => $5)
     and i.author = any($6)
),
totals as (select kind, count(*) as kind_total from m group by kind),
top as (
  select m.*, row_number() over (partition by m.kind
                                 order by m.rank desc, m.item_updated_at desc nulls last,
                                          m.entity_id) as rn
    from m
),
picked as (
  -- One kind cannot flood the box (rn), and the whole answer is bounded (limit)
  -- before anything expensive touches it.
  select * from top where rn <= $7
   order by rank desc, item_updated_at desc nulls last, entity_id
   limit $8
)
select t.kind as group_kind, t.kind_total,
       p.entity_id, i.source_id, i.title, i.item_updated_at, i.synced_at, p.rank,
       -- Only on the rows that survived: ts_headline re-parses the document
       -- text per row, and running it over the match set instead of the page
       -- is the single most expensive mistake available here.
       ts_headline('english', i.title || ' — ' || i.body_text, q.tsq, $9) as snippet
  from totals t
  left join picked p on p.kind = t.kind
  left join sync.live_item i on i.entity_id = p.entity_id
  cross join q
 order by t.kind, p.rank desc nulls last, p.item_updated_at desc nulls last, p.entity_id
```

Three properties of that shape are load-bearing and belong in the module docs:

1. **`totals` LEFT JOIN `picked`** — every matching kind comes back even when the global `limit` left it no row, so `ResultGroup.total` is a true count and `SearchResponse.total` is their sum. A kind with `total > 0` and no hits is a legitimate row; Task 4 keeps the group.
2. **Exactly one match scan.** `m` is materialized and read by `totals` and `top`.
3. **`ts_headline` after the limit**, never before.

Browse mode (`text = None`): drop `q`, drop the `@@` predicate, `0::float4 as rank`, `null as snippet`, and order `m` by `item_updated_at desc nulls last, entity_id`. A browse with **no filters at all** is refused upstream (Task 4) rather than counting the whole corpus.

Binds and safety:

```rust
pub(crate) enum Bind { Text(String), Texts(Vec<String>), Bool(bool), I32(i32), I64(i64) }

struct Builder { sql: String, binds: Vec<Bind> }
impl Builder {
    /// Push a value and get back the placeholder that reads it. The only way
    /// to add a bind, so a placeholder can never drift from its argument.
    fn param(&mut self, bind: Bind) -> String { self.binds.push(bind); format!("${}", self.binds.len()) }
}

/// The one place in knobas where a runtime-built SQL string is executed.
///
/// Sound because of the `Corpus` invariant above: `built.sql` is a
/// concatenation of `&'static str` fragments and `$n` placeholders produced by
/// `Builder::param`. Everything else — every word the user typed, every source
/// id, every kind, every limit — travels as a bind. `tests/sql_containment.rs`
/// fails the build if this type is named anywhere else in the crate.
pub(crate) fn query_as_with<O>(built: SearchSql) -> QueryAs<'static, Postgres, O, PgArguments>
where O: for<'r> FromRow<'r, PgRow> + Send + Unpin
{
    let mut q = sqlx::query_as::<Postgres, O>(AssertSqlSafe(built.sql));
    for bind in built.binds {
        q = match bind {
            Bind::Text(v) => q.bind(v), Bind::Texts(v) => q.bind(v),
            Bind::Bool(v) => q.bind(v), Bind::I32(v) => q.bind(v), Bind::I64(v) => q.bind(v),
        };
    }
    q
}
```

`HEADLINE_OPTS` is a bind, not SQL: `"MaxWords=18, MinWords=8, MaxFragments=1, StartSel=\"\u{1}\", StopSel=\"\u{2}\""`. Passing the options as `$9` sidesteps the question of how to quote a control character inside a SQL literal entirely. `segments()` (the splitter tested above) lives here too, next to the selectors it pairs with.

pub async fn search(&self, query: SearchQuery) -> Result<SearchResponse, SearchError> {
    let started = std::time::Instant::now();
    let query = validate(query)?;                       // ≤ 512 raw chars, limit clamped 1..=200,
                                                        // ≤ 32 sources/kinds — an unbounded box is
                                                        // an unbounded query
    let vocab = Vocabulary::load(&self.pool, self.kinds.clone()).await?;
    let parsed = query::parse(&query.raw, &vocab);
    let filters = query::merge(&parsed, &query.filters);
    let interpreted = ParsedQuery { filters: filters.echo(), ..parsed.query.clone() };

    if let Some(list) = &parsed.list_id { return self.list_response(list, query.limit, interpreted).await; }
    let text = (!parsed.query.text.is_empty()).then_some(parsed.query.text.as_str());
    if text.is_none() && filters.is_empty() {           // the board's job, not a table count
        return Ok(SearchResponse { interpreted, groups: vec![], total: 0, took_ms: … });
    }
    if empty_corpus(&interpreted) { … }                 // asset:/note:/t/> — no rows, still echoed

    let built = sql::search_sql(&[&corpus::LIVE_ITEM], text, parsed.prefix_last_term,
                                &filters, PER_GROUP, query.limit);
    let rows: Vec<RawHit> = sql::query_as_with(built).fetch_all(&self.pool).await?;
    let groups = group::group(rows, &vocab.kinds);

}

```sql
-- one pass, every scan-based list at once (counts and the newest sync stamp
-- the change badge compares against)
select count(*) filter (where item_updated_at >= date_trunc('day', now()))      as changed_today,
       max(synced_at) filter (where item_updated_at >= date_trunc('day', now())) as changed_today_at,
       count(*) filter (where author = any($1) and …)                           as mine,
       …
  from sync.live_item
```

```sql
-- the cross-source join, bounded by construction: the candidate set is
-- "tickets touched in the last two weeks", which is tens of rows, and each
-- probe is one GIN lookup on the key.
select t.entity_id, t.kind, t.source_id, t.title, t.item_updated_at, t.synced_at
  from sync.live_item t
 where t.kind = 'ticket'
   and t.item_updated_at >= now() - interval '14 days'
   and exists (select 1 from sync.live_item o
                where o.source_id <> t.source_id
                  and o.fts @@ websearch_to_tsquery('english', split_part(t.entity_id, ':', 2)))
 order by t.item_updated_at desc
 limit $2
```

```rust
/// Spec §14: "Local search < 100 ms for ~100 k items", and M1's exit criterion.
///
/// `#[ignore]`d: it seeds 100 k rows (tens of seconds) and a timing assertion
/// on a shared CI runner would be a coin flip. Run it deliberately:
///     cargo test -p knobas-search --test perf -- --ignored --nocapture
#[tokio::test]
#[ignore]
async fn a_hundred_thousand_items_answer_in_under_a_hundred_milliseconds() {
    let pool = knobas_db::test_util::test_pool().await;
    knobas_db::migrate::run(&pool).await.unwrap();
    knobas_search::testing::seed_corpus(&pool, 100_000).await.unwrap();
    let s = Searcher::new(pool.clone());

    let cases: &[(&str, &str)] = &[
        ("common word",     "payout"),
        ("two words",       "sepa retry"),
        ("phrase",          "\"sepa retry\""),
        ("still typing",    "pay"),
        ("rare word",       "tombstone"),
        ("filtered",        "/ji payout"),
        ("kind + text",     "kind:pr backoff"),
        ("browse, no text", "/tc"),
        ("mine",            "@me settlement"),
        ("no match",        "zzzznothing"),
    ];
    for _ in 0..3 { s.search(qq("payout")).await.unwrap(); }        // warm the caches

    let mut worst = 0u128;
    for (name, raw) in cases {
        let mut runs: Vec<u128> = Vec::new();
        for _ in 0..10 {
            let t = std::time::Instant::now();
            s.search(qq(raw)).await.unwrap();
            runs.push(t.elapsed().as_millis());
        }
        runs.sort_unstable();
        let p90 = runs[8];
        println!("{name:<16} p50 {:>4} ms  p90 {p90:>4} ms  max {:>4} ms", runs[5], runs[9]);
        worst = worst.max(p90);
        assert!(p90 < 100, "{name} ({raw:?}) took {p90} ms at p90 over 100k items");
    }
    // The other two hot paths of the box, held to the same budget.
    for (name, ms) in [("launcher_board", timed(s.launcher_board()).await),
                       ("smart_lists",    timed(s.smart_lists()).await)] {
        println!("{name:<16} {ms:>4} ms");
        assert!(ms < 100, "{name} took {ms} ms over 100k items");
    }
    println!("worst p90: {worst} ms");
}
```
