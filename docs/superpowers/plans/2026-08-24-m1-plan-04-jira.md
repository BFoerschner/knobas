# knobas M1 stream A — Jira Data Center adapter (read-only) Implementation Plan

> **For agentic workers:** Execute via the **PR loop** in `2026-08-24-knobas-roadmap.md` §3: one `implementer` agent (Opus 5, high) per task in its own worktree/branch → PR → `pr-reviewer` (Opus 5, xhigh) → iterate (max 3 rounds) → squash-merge on approval + green `just check`. Agent definitions: `.claude/agents/`. Steps use checkbox (`- [ ]`) syntax for tracking. Tasks 1–6 are mockd-free and may start immediately; **Task 7 requires stream T's `knobas-mockd` to be merged** (roadmap §2: T is dispatched first).

**Goal:** `crates/knobas-source-jira` — a read-only `Source` adapter speaking **Jira Data Center REST v2** (`/rest/api/2/search` + `startAt` pagination), syncing issues (epics included), comments and worklogs into `sync.item` with an updated-watermark cursor that never loses an item and never re-delivers one it already handed over.

**Architecture:** Six focused modules behind one `Source` impl. `config` parses and validates the source's configuration blob (including the `flavor` field that Cloud will select later); `descriptor` is the static, self-describing template stream F's Add-source form is generated from; `http` is the only module that speaks HTTP (auth header, status→`SourceError`); `model` + `map` turn Jira JSON into `SyncItem`s while keeping the raw record verbatim for `payload`; `cursor` + `jql` own the incremental position; `sync` is the run algorithm, written against an internal `JiraApi` trait so pagination, comment completion and cursor discipline are unit-tested without a server. `source` wires them together.

**Tech Stack:** Rust (edition 2024, toolchain 1.94), `knobas-source` SPI (frozen), `knobas-http` (reqwest 0.13 + retry + governor, orchestrator-owned, read-only), serde/serde_json, chrono, base64, async-trait, tokio (tests), `knobas-mockd` (dev-dependency, Task 7 only).

**Spec:** `docs/superpowers/specs/2026-08-23-knobas-design.md` §3 (sources & sync, DC dialect), §3a (self-describing adapters, raw payload kept), §14 (secrets never leave the keychain), §14a (mock layers). **Contract:** `docs/superpowers/plans/2026-08-24-m1-interfaces.md` §4 (adapter conventions) + §8 rulings P4/P5/P6/P8/P10/P12. **Roadmap:** `docs/superpowers/plans/2026-08-24-knobas-roadmap.md` §2 row A, §4 stack + gotchas. **Endpoint truth:** `testenv/specs/jira-dc-rest.wadl` (official, "Jira 9.17.0", checksum-pinned in `testenv/specs/SHA256SUMS`).

> **CORRECTION (2026-08-25, found in review of PR #15 — task 4 step 3 as written is defective).**
> The cursor's overlap floor must be computed **at the precision the JQL renderer actually uses**. `format_jql_time` emits `%Y-%m-%d %H:%M`, so a floor computed at second precision leaves a sub-minute band in which items are returned by the query but filtered out of `seen`. Against the task 5 loop this oscillates forever — the watermark is dragged backwards each run, an idle incremental emits on every poll, and battery clause 2 fails outright. Floor to the JQL minute in the server's zone, and pin it *through* `format_jql_time` so the test fails if the two precisions ever diverge again. Related: `watermark` must be `max(previous, newest delivered)`, or the same oscillation returns by another door.

M1 additions binding stream A (interfaces doc §4, §6; roadmap §4):

- **Ownership.** Stream A creates and modifies **only** `crates/knobas-source-jira/**`. `crates/knobas-source/**` (SPI), `crates/knobas-http/**`, `crates/knobas-db/migrations/**` and `docs/**` are orchestrator-owned; `crates/knobas-mockd/**` is stream T's. **This stream writes no SQL and needs no migration** — the adapter never touches Postgres.
- **Roadmap §4 gotcha 4, verbatim:** "The primary Jira/Confluence dialect is Data Center (self-hosted), not Cloud — Jira DC REST v2 (`/rest/api/2/search`, `startAt` pagination; the Cloud `/search` 410-removal never applied to DC) and Confluence DC REST v1 (`/rest/api/content` + CQL; no v2 API exists on DC). The `flavor: datacenter|cloud` field in the source config selects the dialect; Cloud (`/search/jql`, `nextPageToken`, no `total`) comes later."
- **Roadmap §4 gotcha 7, verbatim:** "`ts_headline` output is not XSS-safe — escape synced HTML before the webview renders it." Consequence for this stream: the adapter does **not** request `expand=renderedFields`; `body_text` and `payload` carry Jira's own wiki-markup text, never HTML.
- **Endpoint set for M1 (interfaces §5, mockd's Jira subset).** The adapter may call exactly: `GET /rest/api/2/serverInfo`, `GET /rest/api/2/myself`, `GET /rest/api/2/search`, `GET /rest/api/2/issue/{key}`, `GET /rest/api/2/issue/{key}/comment`, `GET /rest/api/2/issue/{key}/worklog`. Query parameters are limited to those the WADL declares for each (see the table in Task 5). mockd answers an undeclared path/verb/parameter with 404/400 **and records a `Violation`**, so an invented endpoint fails this stream's own suite.
- **`write_ops: []`, no `Capability::Write`, no capabilities at all** (P12): M1 is read-only toward every source. `write()` returns `SourceError::Protocol` for everything.
- **Cursor discipline (battery clause 2), verbatim:** "a run that emitted **nothing** returns the cursor it was handed, byte-identical. Watermarks advance only when at least one item was pushed. Cursor content is an opaque adapter-defined string; every adapter uses a **versioned JSON envelope** (`{"v":1,…}`) so a later shape change is detectable and an unrecognised version means 'full sync'."
- **Full sync = reconcile, verbatim:** "After a `cursor: None` run, the engine sweeps rows whose `synced_at` predates the run — adapters need do nothing, but must not fake a full sync by resetting a watermark mid-run." Jira's search API cannot report deletions, so `SyncItem::deleted` is always `false`.
- **Fault classification, verbatim:** "401 **and** 403 → `Unauthorized` (a Jira DC 403 after repeated failures is the CAPTCHA lockout, `X-Authentication-Denied-Reason` — the user must act, so *Re-enter* is the right offer); connect/DNS/TLS/timeout → `Unreachable`; anything else → `Protocol`. Identical mapping from `test_connection` and mid-`sync`."
- **HTTP stack, verbatim:** "`reqwest` 0.13 with rustls + native roots (corporate CAs), `reqwest-middleware` + `reqwest-retry` (3 attempts, exponential, honours `Retry-After`, retries 429/502/503/504 and connect errors only), `governor` for a per-instance rate limit, connect timeout 10 s / request timeout 30 s, `User-Agent: knobas/<version> (<adapter_kind>/<adapter_version>)`." All of it lives in `knobas-http` (P8) and is **read-only** for this stream.
- **Normalization, verbatim:** "`title` = the source's one-line summary; `body_text` = title + description + comment texts joined by blank lines (what FTS indexes, mirroring `knobas-source-mock`); `payload` = the raw record verbatim (§3a re-mapping guarantee); `author` = the source's username string (display-name mapping is M2's people work); `updated_at` = the source's own timestamp, never `now()`."
- **Rate-limit and page-size defaults, verbatim:** "Jira 5 req/s burst 10 … Page sizes: Jira 100."
- **Instance id (P10).** `source_config.id` is the `EntityRef` namespace and is immutable; two Jiras are `jira` and `jira-eu`. The descriptor's `id` comes from `SourceInstance::id`, never from a constant. An issue key renamed upstream is accepted M1 breakage (new entity, old one swept).
- **Secrets (§14, interfaces §3).** The secret arrives as `SourceInstance::secret: Option<String>` and is used for exactly one thing: the `Authorization` header. It is never logged, never put in a URL, never written into `payload`, `config`, an error message or a `Debug` output. The type that holds it has a hand-written `Debug` that prints `<redacted>`, pinned by a test.
- **Error hygiene.** Response bodies quoted into `SourceError::Protocol` are truncated to 300 characters — a DC instance behind an SSO proxy answers with an HTML login page, and that must not become the message the user reads.
- **No `unwrap()`/`expect()` on any network or parsing path.** The single sanctioned `expect` is serializing this crate's own cursor struct, which cannot fail.

`crates/knobas-source-jira/src/config.rs` (above the test module):
```rust
//! What the Add-source form fills in, and what the adapter is allowed to
//! believe about it.
//!
//! Nothing secret lives here (spec §14): the password or PAT is in the OS
//! keychain and reaches the adapter as `SourceInstance::secret`. `username` is
//! not a secret -- it is half of a Basic auth pair and is displayed in the
//! sources view.

use knobas_source::SourceError;

/// Which Jira product this instance is (roadmap §4 gotcha 4).
#[derive(Debug, Clone, Copy, PartialEq, Eq, Default, serde::Serialize, serde::Deserialize)]
#[serde(rename_all = "lowercase")]
pub enum Flavor {
    /// Data Center / Server: REST v2, `/rest/api/2/search`, `startAt` paging.
    #[default]
    Datacenter,
    /// Cloud: REST v3, `/rest/api/3/search/jql`, `nextPageToken`, no `total`.
    /// Parsed and refused in M1 -- see [`JiraConfig::validate`].
    Cloud,
}

/// One Jira source's configuration blob (`knobas.source_config.config`).
#[derive(Debug, Clone, PartialEq, Eq, serde::Serialize, serde::Deserialize)]
#[serde(deny_unknown_fields, default)]
pub struct JiraConfig {
    pub flavor: Flavor,
    /// Project keys to sync. Empty means "everything the credential can see".
    /// Mutually exclusive with [`Self::jql_filter`].
    pub projects: Vec<String>,
    /// Any JQL, without an `ORDER BY`; the adapter appends its own.
    pub jql_filter: Option<String>,
    /// Required for `AuthMethod::UserPassword`, unused for a PAT.
    pub username: Option<String>,
    /// The instance's Epic Link custom field (`customfield_10008` on many DC
    /// instances). Naming it adds it to the requested `fields=` list, so epic
    /// membership survives in `payload` for M2's link work. Discovering the id
    /// automatically needs `GET /rest/api/2/field`, which is outside M1's
    /// endpoint set.
    pub epic_link_field: Option<String>,
    /// `maxResults` per `/search` page (interfaces §4.1 default: 100).
    pub page_size: u32,
    /// Per-instance rate limit (interfaces §4.1 default: 5 req/s, burst 10).
    pub rate_per_sec: u32,
    pub rate_burst: u32,
    pub connect_timeout_secs: u64,
    pub request_timeout_secs: u64,
}

impl Default for JiraConfig {
    fn default() -> Self {
        Self {
            flavor: Flavor::Datacenter,
            projects: Vec::new(),
            jql_filter: None,
            username: None,
            epic_link_field: None,
            page_size: 100,
            rate_per_sec: 5,
            rate_burst: 10,
            connect_timeout_secs: 10,
            request_timeout_secs: 30,
        }
    }
}

impl JiraConfig {
    /// Parse and validate `knobas.source_config.config` for a Jira instance.
    pub fn from_json(value: &serde_json::Value) -> Result<Self, SourceError> {
        let cfg: Self = serde_json::from_value(value.clone())
            .map_err(|e| SourceError::Protocol(format!("jira configuration is not valid: {e}")))?;
        cfg.validate()?;
        Ok(cfg)
    }

    fn validate(&self) -> Result<(), SourceError> {
        let bad = |m: String| Err(SourceError::Protocol(m));
        if self.flavor == Flavor::Cloud {
            return bad(
                "jira flavor \"cloud\" is not implemented yet: Cloud speaks \
                 /rest/api/3/search/jql with nextPageToken paging and accountId users, which is \
                 a different dialect from Data Center's /rest/api/2/search. Set flavor to \
                 \"datacenter\"."
                    .to_owned(),
            );
        }
        if !self.projects.is_empty() && self.jql_filter.is_some() {
            return bad(
                "set either projects or jql_filter, not both -- the filter already decides the \
                 scope"
                    .to_owned(),
            );
        }
        for p in &self.projects {
            if !is_project_key(p) {
                return bad(format!(
                    "{p:?} is not a Jira project key (A-Z, 0-9 and _, starting with a letter, \
                     at most 32 characters)"
                ));
            }
        }
        if let Some(filter) = &self.jql_filter {
            if filter.trim().is_empty() {
                return bad("jql_filter is blank".to_owned());
            }
            if filter.to_ascii_lowercase().contains("order by") {
                return bad(
                    "jql_filter must not carry an ORDER BY: the adapter appends \
                     ORDER BY updated ASC, which is what makes startAt paging safe"
                        .to_owned(),
                );
            }
        }
        if let Some(field) = &self.epic_link_field {
            if field.is_empty() || !field.chars().all(|c| c.is_ascii_alphanumeric() || c == '_') {
                return bad(format!(
                    "{field:?} is not a bare Jira field id (letters, digits and _), and it is \
                     pasted into the fields= query parameter"
                ));
            }
        }
        if self.page_size == 0 || self.page_size > 1000 {
            return bad(format!(
                "page_size {} is outside 1..=1000 (Jira DC clamps at its own \
                 jira.search.views.default.max anyway)",
                self.page_size
            ));
        }
        if self.rate_per_sec == 0 {
            return bad("rate_per_sec must be at least 1".to_owned());
        }
        if self.rate_burst == 0 {
            return bad("rate_burst must be at least 1".to_owned());
        }
        if self.connect_timeout_secs == 0 || self.request_timeout_secs == 0 {
            return bad("timeouts must be at least 1 second".to_owned());
        }
        Ok(())
    }
}

//! Everything else is pure: the sync run is written against a `JiraApi` trait

use knobas_source::{AuthMethod, SourceError};

/// One `Authorization` header value.
///
/// Spec §14: the secret is never displayed, so this type is opaque and its
/// [`std::fmt::Debug`] is hand-written. Deriving `Debug` anywhere up the stack
/// then cannot leak a PAT into a log line.
pub(crate) struct Credential(String);

impl Credential {
    pub(crate) fn header_value(&self) -> &str {
        &self.0
    }
}

impl std::fmt::Debug for Credential {
    fn fmt(&self, f: &mut std::fmt::Formatter<'_>) -> std::fmt::Result {

/// Build the header for the auth method the source was configured with.
///
/// A missing secret is [`SourceError::Unauthorized`], which is exactly the
/// state interfaces §3 calls `missing_secret`: the sources view offers
/// *Re-enter*, and the scheduler does not back off over it.
pub(crate) fn credential(
    auth: AuthMethod,
    username: Option<&str>,
    secret: Option<&str>,
) -> Result<Credential, SourceError> {
    let secret = secret.ok_or(SourceError::Unauthorized)?;
    match auth {
        // Jira DC >= 8.14: personal access tokens are Bearer tokens.
        AuthMethod::Pat => Ok(Credential(format!("Bearer {secret}"))),
        AuthMethod::UserPassword => {
            let user = username.ok_or_else(|| {
                SourceError::Protocol(
                    "user + password authentication needs a username in the source configuration"
                        .to_owned(),
                )
            })?;
            use base64::Engine as _;
            let encoded =
                base64::engine::general_purpose::STANDARD.encode(format!("{user}:{secret}"));
            Ok(Credential(format!("Basic {encoded}")))
        }
        // Declared in neither `descriptor_template().auth_methods` nor reachable
        // from the Add-source form; refused rather than guessed at.
        other => Err(SourceError::Protocol(format!(
            "{other:?} authentication is not supported for Jira Data Center; use a personal \
             access token or user + password"
        ))),
    }
}

pub(crate) struct JiraHttp {
    /// Base URL without a trailing slash, e.g. `https://jira.example.com/jira`.
    base: String,
    client: knobas_http::Client,
    credential: Credential,
}

impl JiraHttp {
    pub(crate) fn new(
        base_url: &str,
        cfg: &crate::JiraConfig,
        credential: Credential,
    ) -> Result<Self, SourceError> {
        let base = base_url.trim().trim_end_matches('/').to_owned();
        if !(base.starts_with("http://") || base.starts_with("https://")) {
            return Err(SourceError::Protocol(format!(
                "{base_url:?} is not a URL; it must start with https:// (or http:// on a local \
                 test instance)"
            )));
        }
        // ADAPT HERE, and only here: the constructor name and the field names
        // come from the contract PR's `crates/knobas-http/src/lib.rs` (P8).
        // What this crate needs from it, per interfaces §4.1: rustls + native
        // roots, reqwest-retry (3 attempts, exponential, honours Retry-After,
        // retries 429/502/503/504 and connect errors only), a governor rate
        // limit, connect/request timeouts, and the
        // `knobas/<version> (<adapter_kind>/<adapter_version>)` User-Agent.
        let client = knobas_http::client(knobas_http::HttpConfig {
            adapter_kind: crate::ADAPTER_KIND.to_owned(),
            adapter_version: crate::ADAPTER_VERSION.to_owned(),
            rate_per_sec: cfg.rate_per_sec,
            rate_burst: cfg.rate_burst,
            connect_timeout: std::time::Duration::from_secs(cfg.connect_timeout_secs),
            request_timeout: std::time::Duration::from_secs(cfg.request_timeout_secs),
        })
        .map_err(|e| SourceError::Protocol(format!("could not build an HTTP client: {e}")))?;
        Ok(Self { base, client, credential })
    }

    /// `GET <base>/<path>?<query>` as JSON.
    ///
    /// `path` is always one of the six endpoints the WADL declares for M1 (see
    /// Task 5); `query` carries only parameters that endpoint declares.
    pub(crate) async fn get_json<T: serde::de::DeserializeOwned>(
        &self,
        path: &str,
        query: &[(&str, String)],
    ) -> Result<T, SourceError> {
        let url = format!("{}/{path}", self.base);
        let response = self
            .client
            .get(&url)
            .query(query)
            .header(reqwest::header::AUTHORIZATION, self.credential.header_value())
            .header(reqwest::header::ACCEPT, "application/json")
            .send()
            .await
            .map_err(classify_transport)?;
        let status = response.status().as_u16();
        let headers = response.headers().clone();
        let body = response.text().await.map_err(classify_transport)?;
        if !(200..300).contains(&status) {
            return Err(classify_status(status, &headers, &body));
        }
        serde_json::from_str(&body).map_err(|e| {
            SourceError::Protocol(format!(
                "{path} did not answer with the shape the Jira REST v2 contract documents: {e}"
            ))
        })
    }
}

/// Interfaces §4.1: connect / DNS / TLS / timeout are `Unreachable`; a body
/// that is not what the contract documents is `Protocol`.
///
/// ADAPT HERE if `knobas-http` exports an equivalent: delete this and call it.
/// The error type is whatever `knobas_http::Client::send` returns.
fn classify_transport<E: std::fmt::Display>(err: E) -> SourceError {
    let text = err.to_string();
    let lower = text.to_lowercase();
    if lower.contains("decoding") || lower.contains("body") && lower.contains("json") {
        SourceError::Protocol(text)
    } else {
        SourceError::Unreachable(text)
    }
}

/// Interfaces §4.1: 401 **and** 403 are `Unauthorized`; everything else is
/// `Protocol`, carrying Jira's own words so the diagnostics view is useful.
pub(crate) fn classify_status(
    status: u16,
    headers: &reqwest::header::HeaderMap,
    body: &str,
) -> SourceError {
    match status {
        401 | 403 => {
            // `SourceError::Unauthorized` carries no detail (it crosses the SPI
            // as a bare variant), so the reason goes to the log. The CAPTCHA
            // lockout is the one a user cannot fix by re-typing the password --
            // they have to log in through the browser once.
            for header in ["X-Authentication-Denied-Reason", "X-Seraph-LoginReason"] {
                if let Some(reason) = headers.get(header).and_then(|v| v.to_str().ok()) {
                    tracing::warn!(header, reason, "jira refused the credential");
                }
            }
            SourceError::Unauthorized
        }
        429 => SourceError::Protocol(format!(
            "jira is rate-limiting this source (429) and the request still failed after retries: \
             {}. Lower rate_per_sec in the source configuration.",
            jira_message(body)
        )),
        _ => SourceError::Protocol(format!("jira returned {status}: {}", jira_message(body))),
    }
}

/// Jira's error envelope, `{"errorMessages":[…],"errors":{…}}` (WADL: every
/// 4xx representation). Anything else is quoted, truncated.
pub(crate) fn jira_message(body: &str) -> String {
    #[derive(serde::Deserialize)]
    #[serde(rename_all = "camelCase")]
    struct Envelope {
        #[serde(default)]
        error_messages: Vec<String>,
        #[serde(default)]
        errors: serde_json::Map<String, serde_json::Value>,
    }
    if let Ok(envelope) = serde_json::from_str::<Envelope>(body) {
        let mut parts = envelope.error_messages;
        parts.extend(
            envelope
                .errors
                .iter()
                .map(|(field, message)| format!("{field}: {}", message.as_str().unwrap_or_default())),
        );
        if !parts.is_empty() {
            return truncate(&parts.join("; "));
        }
    }
    truncate(body.trim())
}

fn truncate(s: &str) -> String {
    const LIMIT: usize = 300;
    if s.chars().count() <= LIMIT {
        return s.to_owned();
    }
    let head: String = s.chars().take(LIMIT).collect();
    format!("{head}… (truncated)")
}

```rust
//! Jira's timestamps in, JQL's date literals out.
//!
//! Two formats, and neither is RFC 3339:
//!
//! * **Responses** stamp `2026-08-22T13:48:00.000+0200` -- an offset without a
//!   colon.
//! * **JQL** takes `"yyyy-MM-dd HH:mm"` with **no zone at all**, read in the
//!   user's own time zone, at one-minute resolution. Both facts shape the
//!   cursor: the zone is taken from `serverInfo.serverTime`, and the minute
//!   resolution is why the watermark is queried with a two-minute overlap
//!   (interfaces doc §4.2).

use chrono::{DateTime, FixedOffset, Utc};

/// Parse a Jira timestamp into UTC. Tolerates `+0200`, `+02:00` and `Z`, with
/// or without a fractional part.
pub(crate) fn parse_jira_time(s: &str) -> Option<DateTime<Utc>> {
    DateTime::parse_from_str(s, "%Y-%m-%dT%H:%M:%S%.f%z")
        .or_else(|_| DateTime::parse_from_rfc3339(s))
        .ok()
        .map(|t| t.with_timezone(&Utc))
}

/// The UTC offset a Jira timestamp was written in, in seconds.
pub(crate) fn parse_offset_secs(s: &str) -> Option<i32> {
    DateTime::parse_from_str(s, "%Y-%m-%dT%H:%M:%S%.f%z")
        .or_else(|_| DateTime::parse_from_rfc3339(s))
        .ok()
        .map(|t| t.offset().local_minus_utc())
}

/// Render `t` as the zone-less JQL literal Jira will read back in the server's
/// own time zone.
pub(crate) fn format_jql_time(t: DateTime<Utc>, offset_secs: i32) -> String {
    let zone = FixedOffset::east_opt(offset_secs).unwrap_or_else(|| {
        FixedOffset::east_opt(0).expect("UTC is a valid fixed offset")
    });
    t.with_timezone(&zone).format("%Y-%m-%d %H:%M").to_string()
}

```rust
//! Serde views of the six Data Center responses this adapter reads.
//!
//! Every issue and comment keeps **both** its raw [`serde_json::Value`] and a
//! typed view of the handful of fields the adapter uses. The raw half is what
//! `SyncItem::payload` carries (spec §3a: "raw payload kept", so a later,
//! smarter mapping can re-project existing data without re-syncing); the typed
//! half is what the mapping and the cursor read. Deriving both from one
//! `Deserialize` keeps them from drifting.
//!
//! Nothing here is `deny_unknown_fields`: a Jira instance carries hundreds of
//! custom fields and every upgrade adds more.

use serde::Deserialize;
use serde_json::Value;

/// `GET /rest/api/2/search` — the classic `startAt`/`total` envelope
/// (WADL: `SearchResultsBean`). Cloud's `/search/jql` has no `total` and pages
/// with `nextPageToken` instead; that is the other dialect, refused in
/// [`crate::JiraConfig::validate`].
///
/// The echoed `startAt`/`maxResults` are deliberately not modelled: the run
/// advances its own offset by how many issues actually arrived, which is
/// correct even when the server clamped `maxResults` to its own limit. Only
/// fields something reads are kept, here and below -- an unread field is a
/// `dead_code` warning under `just check`'s library clippy pass, and the raw
/// `payload` carries everything regardless.
#[derive(Debug, Deserialize)]
pub(crate) struct SearchPage {
    #[serde(default)]
    pub total: u32,
    #[serde(default)]
    pub issues: Vec<RawIssue>,
}

/// One issue: the record as it arrived, plus the fields the adapter reads.
#[derive(Debug, Clone)]
pub(crate) struct RawIssue {
    pub raw: Value,
    pub issue: Issue,
}

impl<'de> Deserialize<'de> for RawIssue {
    fn deserialize<D: serde::Deserializer<'de>>(d: D) -> Result<Self, D::Error> {
        let raw = Value::deserialize(d)?;
        let issue = Issue::deserialize(&raw).map_err(serde::de::Error::custom)?;
        Ok(Self { raw, issue })
    }
}

impl RawIssue {
    /// Replace the comment container in both views, after the dedicated
    /// endpoint filled in what `/search` truncated.
    pub(crate) fn set_comments(&mut self, comments: Vec<RawComment>) {
        let container = serde_json::json!({
            "startAt": 0,
            "maxResults": comments.len(),
            "total": comments.len(),
            "comments": comments.iter().map(|c| c.raw.clone()).collect::<Vec<_>>(),
        });
        self.fields_mut().insert("comment".to_owned(), container);
        self.issue.fields.comment = Some(CommentContainer {
            total: Some(comments.len() as u32),
            comments,
        });
    }

    /// Same for worklogs. No worklog field feeds `body_text` (interfaces §4.1
    /// lists title + description + comments), so the typed view exists only to
    /// answer "was this truncated?" -- after a completion, it is not.
    pub(crate) fn set_worklogs(&mut self, worklogs: Vec<Value>) {

            "startAt": 0,
            "maxResults": total,
            "total": total,
            "worklogs": worklogs.clone(),
        });
        self.fields_mut().insert("worklog".to_owned(), container);
        self.issue.fields.worklog =
            Some(WorklogContainer { total: Some(total as u32), worklogs });
    }

    fn fields_mut(&mut self) -> &mut serde_json::Map<String, Value> {
        if !self.raw.get("fields").map(Value::is_object).unwrap_or(false) {
            if let Some(object) = self.raw.as_object_mut() {
                object.insert("fields".to_owned(), Value::Object(serde_json::Map::new()));
            }
        }
        self.raw
            .get_mut("fields")
            .and_then(Value::as_object_mut)
            .expect("fields was just ensured to be an object")
    }
}

pub(crate) fn to_sync_item(source_id: &str, base_url: &str, raw: &RawIssue) -> SyncItem {

```rust
//! The incremental position: `{"v":1,…}`, opaque to everything but this crate.
//!
//! ```text
//! {"v":1,
//!  "updated_to":"2026-08-22T11:48:00Z",   // the newest `updated` delivered
//!  "tz_offset_secs":7200,                 // the zone that watermark was queried in
//!  "seen":[{"k":"PAY-231","u":"2026-08-22T11:48:00Z"}]}
//! ```
//!
//! `seen` is the price of correctness. JQL resolves to the minute, so the next
//! query must start *before* the watermark (interfaces §4.2: the two-minute
//! overlap is mandatory) -- and everything in that window comes back. Dropping
//! the pairs already delivered turns re-delivery from a contract violation
//! (battery clause 2: an idle incremental emits nothing) into an invisible
//! detail.

use chrono::{DateTime, Utc};

/// Bump when the envelope's shape changes: an unrecognised version reads as
/// "no cursor", which is a full sync.
pub(crate) const CURSOR_VERSION: u8 = 1;

/// Interfaces §4.2: "**JQL time resolution is one minute**, so an
/// exact-boundary watermark drops items. Re-delivery is free -- upserts are
/// idempotent."
const OVERLAP_MINUTES: i64 = 2;

/// Used for the one run after the server's UTC offset changed (a daylight
/// saving shift is at most an hour), so no item falls in the seam.
const DST_OVERLAP_MINUTES: i64 = 65;

/// How many `(key, updated)` pairs the envelope remembers. Beyond this a mass
/// edit inside one overlap window may be delivered twice -- upserts are
/// idempotent, so the cost is bandwidth, not correctness.
pub(crate) const SEEN_CAP: usize = 500;

#[derive(Debug, Clone, PartialEq, Eq, serde::Serialize, serde::Deserialize)]
pub(crate) struct JiraCursor {
    pub v: u8,
    /// The newest `fields.updated` this source has delivered, or `None` after a
    /// run that found nothing at all.
    pub updated_to: Option<DateTime<Utc>>,
    /// The server's UTC offset when that watermark was taken.
    pub tz_offset_secs: i32,
    /// What was delivered inside the overlap window, sorted by key.
    pub seen: Vec<Seen>,
}

#[derive(Debug, Clone, PartialEq, Eq, serde::Serialize, serde::Deserialize)]
pub(crate) struct Seen {
    pub k: String,
    pub u: DateTime<Utc>,
}

impl JiraCursor {
    /// A cursor for a source that has never delivered anything.
    pub(crate) fn empty(tz_offset_secs: i32) -> Self {
        Self { v: CURSOR_VERSION, updated_to: None, tz_offset_secs, seen: Vec::new() }
    }

    /// `None` for anything this version does not recognise -- which the caller
    /// reads as "full sync".
    pub(crate) fn parse(raw: &str) -> Option<Self> {
        let cursor: Self = serde_json::from_str(raw).ok()?;
        (cursor.v == CURSOR_VERSION).then_some(cursor)
    }

    pub(crate) fn encode(&self) -> String {
        serde_json::to_string(self).expect("a cursor is plain data and always serializes")
    }

    /// The lower bound of the next `updated >=` clause.
    pub(crate) fn since(&self, current_offset_secs: i32) -> Option<DateTime<Utc>> {
        let watermark = self.updated_to?;
        let minutes = if current_offset_secs == self.tz_offset_secs {
            OVERLAP_MINUTES
        } else {
            DST_OVERLAP_MINUTES
        };
        Some(watermark - chrono::Duration::minutes(minutes))
    }

    /// Was this exact version of this issue already handed to the sink?
    ///
    /// An issue edited twice within the same second is missed here; the next
    /// distinct edit brings it back, and the item was already upserted once.
    pub(crate) fn already_delivered(&self, key: &str, updated: Option<DateTime<Utc>>) -> bool {
        let Some(updated) = updated else { return false };
        self.seen.iter().any(|s| s.u == updated && s.k == key)
    }

    /// The cursor for a run that delivered something.
    pub(crate) fn advanced(
        watermark: DateTime<Utc>,
        tz_offset_secs: i32,
        delivered: &[(String, DateTime<Utc>)],
    ) -> Self {
        let floor = watermark - chrono::Duration::minutes(OVERLAP_MINUTES);
        let mut seen: Vec<Seen> = delivered
            .iter()
            .filter(|(_, u)| *u >= floor)
            .map(|(k, u)| Seen { k: k.clone(), u: *u })
            .collect();
        // Newest first, so the cap drops the entries least likely to come back.
        seen.sort_by(|a, b| b.u.cmp(&a.u).then_with(|| a.k.cmp(&b.k)));
        seen.truncate(SEEN_CAP);
        // Then by key, so the same delivered set always encodes to the same bytes.
        seen.sort_by(|a, b| a.k.cmp(&b.k));
        Self { v: CURSOR_VERSION, updated_to: Some(watermark), tz_offset_secs, seen }
    }
}

//! The one function that writes JQL.
//!
//! Data Center only (roadmap §4 gotcha 4): `/rest/api/2/search` takes a `jql`
//! parameter and pages with `startAt`. Cloud's `/rest/api/3/search/jql` takes a
//! bounded JQL and pages with `nextPageToken`; when that flavor is implemented
//! it gets its own renderer beside this one, because the two differ in what the
//! query may contain, not just in how it is sent.

use chrono::{DateTime, Utc};

use crate::JiraConfig;

/// `<scope> AND updated >= "<since>" ORDER BY updated ASC`, with either half
/// omitted when it does not apply.
pub(crate) fn build_jql(
    cfg: &JiraConfig,
    since: Option<DateTime<Utc>>,
    server_offset_secs: i32,
) -> String {
    let mut clauses: Vec<String> = Vec::new();
    if let Some(filter) = &cfg.jql_filter {
        clauses.push(format!("({})", filter.trim()));
    } else if !cfg.projects.is_empty() {
        let list = cfg
            .projects
            .iter()
            .map(|p| format!("\"{p}\""))
            .collect::<Vec<_>>()
            .join(", ");
        clauses.push(format!("project in ({list})"));
    }
    if let Some(since) = since {
        clauses.push(format!(
            "updated >= \"{}\"",
            crate::time::format_jql_time(since, server_offset_secs)
        ));
    }
    // ASC is what makes startAt paging safe over a live index; see the tests.
    if clauses.is_empty() {
        "ORDER BY updated ASC".to_owned()
    } else {
        format!("{} ORDER BY updated ASC", clauses.join(" AND "))
    }
}

Two consequences worth naming:

- **`expand=renderedFields` is deliberately not sent.** It returns Jira's HTML rendering, and gotcha 7 is exactly about HTML reaching the webview. `description` and comment bodies in REST v2 are wiki markup — plain text, which is what FTS wants and what the §3a generic detail view can project safely.
- **Worklogs cannot be paged in M1.** The WADL declares no query parameters on that resource, so sending `startAt` would be an invented parameter. The adapter takes the page the server gives and leaves `fields.worklog.total` as the server reported it, so a truncation is visible in the payload. Full worklog history belongs to M3's time work, which has `GET /rest/api/2/worklog/updated` + `POST /rest/api/2/worklog/list` for exactly this (both present in the WADL, both outside M1's mockd subset).

//!
//! A trait rather than a direct dependency on [`crate::http::JiraHttp`],

        max_results: u32,

        &self,
        key: &str,
        start_at: u32,
        max_results: u32,
    ) -> Result<CommentPage, SourceError>;
    /// `GET /rest/api/2/issue/{key}/worklog` — no parameters exist on this
    /// resource, so there is no paging to do.

```rust
//! One incremental (or full) sync run.
//!
//! The shape, and why each part is there:
//!
//! 1. `GET serverInfo` — the server's UTC offset, because JQL date literals
//!    carry no zone.
//! 2. Read the cursor. Unreadable or absent ⇒ full sync (interfaces §4.1).
//! 3. Query `updated >= watermark − 2 minutes ORDER BY updated ASC`, paging with
//!    `startAt` until `total` is reached.
//! 4. Drop what the overlap re-delivered, complete truncated comment/worklog
//!    containers, push the rest into the sink.
//! 5. If nothing was pushed, hand back the cursor byte-identically. Otherwise
//!    advance the watermark to the newest `updated` **delivered** — never to
//!    `now()`, because Jira's search index lags its own writes by seconds and
//!    an issue updated in that gap would be skipped forever.

use chrono::{DateTime, Utc};
use knobas_source::{Sink, SourceError};

use crate::api::JiraApi;
use crate::cursor::JiraCursor;
use crate::jql::build_jql;
use crate::map;
use crate::model::{RawIssue, SearchPage, ServerInfo};
use crate::{JiraConfig, time::parse_jira_time};

/// The fields `/search` is asked for. Explicit rather than Jira's `*navigable`
/// default: a deterministic payload, a smaller response, and no surprise when
/// an instance changes its navigable set. `comment` and `worklog` are in the
/// list so the common case costs one request per page instead of one per issue.
const BASE_FIELDS: &str = "summary,description,issuetype,status,priority,resolution,\
resolutiondate,assignee,reporter,created,updated,labels,project,parent,components,fixVersions,\
issuelinks,subtasks,timeoriginalestimate,timespent,timetracking,comment,worklog";

/// A stop so a server that keeps reporting "more" cannot spin a run forever.
/// At the default page size this is half a million issues.
const MAX_PAGES: u32 = 5_000;

pub(crate) struct SyncRun<'a> {
    pub api: &'a (dyn JiraApi + 'a),
    pub cfg: &'a JiraConfig,
    /// The instance id — the `EntityRef` namespace (P10), not the adapter kind.
    pub source_id: &'a str,
    pub base_url: &'a str,
}

impl SyncRun<'_> {
    pub(crate) async fn run(
        &self,
        cursor: Option<String>,
        sink: &mut (dyn Sink + Send),
    ) -> Result<String, SourceError> {
        let server: ServerInfo = self.api.server_info().await?;
        let offset = server.offset_secs();
        let previous = cursor.as_deref().and_then(JiraCursor::parse);
        let since = previous.as_ref().and_then(|c| c.since(offset));
        let jql = build_jql(self.cfg, since, offset);
        let fields = self.fields();

        let mut start_at: u32 = 0;
        let mut pages: u32 = 0;
        let mut emitted: usize = 0;
        let mut delivered: Vec<(String, DateTime<Utc>)> = Vec::new();
        let mut watermark: Option<DateTime<Utc>> = None;

        loop {
            let page: SearchPage = self
                .api
                .search(&jql, start_at, self.cfg.page_size, &fields)
                .await?;
            let total = page.total;
            let returned = page.issues.len() as u32;
            if returned == 0 {
                break;
            }
            for mut raw in page.issues {
                let updated = raw
                    .issue
                    .fields
                    .updated
                    .as_deref()
                    .and_then(parse_jira_time);
                // The overlap exists so nothing is missed; this is what keeps it
                // from also meaning "everything arrives twice".
                if previous
                    .as_ref()
                    .is_some_and(|c| c.already_delivered(&raw.issue.key, updated))
                {
                    continue;
                }
                self.complete(&mut raw).await?;
                let item = map::to_sync_item(self.source_id, self.base_url, &raw);
                // Sink failures are never swallowed (SPI doc on `Source::sync`).
                sink.item(item).await?;
                emitted += 1;
                if let Some(u) = updated {
                    delivered.push((raw.issue.key.clone(), u));
                    watermark = Some(watermark.map_or(u, |w| w.max(u)));
                }
            }
            start_at += returned;
            pages += 1;
            if start_at >= total || pages >= MAX_PAGES {
                break;
            }
        }

        match (emitted, watermark) {
            // Battery clause 2: nothing happened, so the position did not move.
            // Returning the *input string* rather than a re-encoded struct makes
            // that byte-identical by construction.
            (0, _) => Ok(cursor.unwrap_or_else(|| JiraCursor::empty(offset).encode())),
            // Items arrived but not one carried a readable `updated`; advancing
            // to anything would be a guess.
            (_, None) => Ok(cursor.unwrap_or_else(|| JiraCursor::empty(offset).encode())),
            (_, Some(w)) => Ok(JiraCursor::advanced(w, offset, &delivered).encode()),
        }
    }

    /// Fill in what `/search` truncated.
    ///
    /// A container that is absent is treated as truncated: a server that
    /// ignored `fields=comment` must not be read as "this issue has no
    /// comments" — that would silently drop the discussion out of the search
    /// corpus.
    async fn complete(&self, raw: &mut RawIssue) -> Result<(), SourceError> {
        let key = raw.issue.key.clone();

        let comments_truncated = match &raw.issue.fields.comment {
            None => true,
            Some(c) => c.total.unwrap_or(0) as usize > c.comments.len(),
        };
        if comments_truncated {
            let mut all = Vec::new();
            let mut start_at: u32 = 0;
            loop {
                let page = self.api.comments(&key, start_at, self.cfg.page_size).await?;
                let returned = page.comments.len() as u32;
                if returned == 0 {
                    break;
                }
                all.extend(page.comments);
                start_at += returned;
                if start_at >= page.total {
                    break;
                }
            }
            raw.set_comments(all);
        }

        let worklogs_truncated = match &raw.issue.fields.worklog {
            None => true,
            Some(w) => w.total.unwrap_or(0) as usize > w.worklogs.len(),

            // work uses /rest/api/2/worklog/updated + /worklog/list instead.
            let page = self.api.worklogs(&key).await?;
            raw.set_worklogs(page.worklogs);
        }
        Ok(())
    }

    fn fields(&self) -> String {
        let mut fields = BASE_FIELDS.to_owned();
        if let Some(extra) = &self.cfg.epic_link_field {
            fields.push(',');
            fields.push_str(extra);
        }
        fields
    }

use knobas_source::instance::SourceInstance;
use knobas_source::{
    ConnectionInfo, Cursor, Sink, Source, SourceDescriptor, SourceError, WriteOp,
};

use crate::api::JiraApi;
use crate::http::{self, JiraHttp};
use crate::sync::SyncRun;
use crate::{JiraConfig, descriptor_template};

/// One configured Jira Data Center instance.
pub struct JiraSource {
    /// The instance id: the `EntityRef` namespace of every item this source
    /// emits, immutable once chosen (P10).
    id: String,
    display_name: String,
    /// Without a trailing slash, so `/browse/<key>` composes cleanly.
    base_url: String,
    cfg: JiraConfig,
    http: JiraHttp,
}

/// Build an adapter from a stored source configuration plus the secret stream F
/// read out of the keychain (interfaces §4.2).
///
/// Everything that can be wrong with the configuration is wrong *here* — a
/// missing secret, an unsupported flavor, a base URL that is not one — so a
/// scheduled run never discovers it mid-sync.
pub fn build(instance: SourceInstance) -> Result<Box<dyn Source>, SourceError> {
    let cfg = JiraConfig::from_json(&instance.config)?;
    let credential = http::credential(
        instance.auth,
        cfg.username.as_deref(),
        instance.secret.as_deref(),
    )?;
    let http = JiraHttp::new(&instance.base_url, &cfg, credential)?;
    Ok(Box::new(JiraSource {
        id: instance.id,
        display_name: instance.display_name,
        base_url: instance.base_url.trim().trim_end_matches('/').to_owned(),
        cfg,
        http,
    }))
}

#[async_trait::async_trait]
impl Source for JiraSource {
    fn descriptor(&self) -> SourceDescriptor {
        SourceDescriptor {
            id: self.id.clone(),
            name: self.display_name.clone(),
            ..descriptor_template()
        }
    }

    async fn test_connection(&self) -> Result<ConnectionInfo, SourceError> {
        // `myself` first: it is the call that fails with 401 on a bad
        // credential, and it is what the Add-source flow shows as "connected as".
        let me = self.http.myself().await?;
        let server = self.http.server_info().await?;
        let version = server.version.clone();
        Ok(ConnectionInfo {
            account: me.name.or(me.display_name),
            server_version: version.clone(),
            // Jira DC does publish PAT expiry, but only through
            // /rest/pat/latest/tokens, which is outside M1's endpoint set (it is
            // not in mockd's Jira subset). The credential-health strip shows the
            // countdown as soon as that endpoint is added.
            secret_expires_at: None,
            detail: Some(format!(
                "{} {}",
                server.deployment_type.unwrap_or_else(|| "Jira".to_owned()),
                version.unwrap_or_else(|| "(unknown version)".to_owned())
            )),
        })
    }

    async fn sync(
        &self,
        cursor: Option<Cursor>,
        sink: &mut (dyn Sink + Send),
    ) -> Result<Cursor, SourceError> {
        SyncRun {
            api: &self.http,
            cfg: &self.cfg,
            source_id: &self.id,
            base_url: &self.base_url,
        }
        .run(cursor, sink)
        .await
    }

    async fn write(&self, op: WriteOp) -> Result<(), SourceError> {
        // M1 is read-only toward every source (interfaces §4.1); the descriptor
        // declares no write ops, so refusing here is the contract, not a gap.
        // Jira write-back (transition, comment, create) is M2.
        Err(SourceError::Protocol(format!(
            "the Jira adapter is read-only in this version and does not support {:?}",
            op.identifier()
        )))
    }
}

### Gaps and deliberate narrowings — flagged, not hidden

1. **PAT expiry is always `None`.** `ConnectionInfo::secret_expires_at` needs `/rest/pat/latest/tokens`, which is neither in the vendored WADL (it covers `api/2` and `auth/1`) nor in mockd's Jira subset. The credential-health countdown (design §3) therefore shows nothing for Jira in M1. Closing it is one endpoint in mockd plus one call here.
2. **Worklogs cannot be paged.** The WADL declares no query parameters on `GET /rest/api/2/issue/{key}/worklog`, so an issue with more worklogs than the server's default page returns a truncated list; `fields.worklog.total` keeps that visible in the payload. M3's time work uses `/rest/api/2/worklog/updated` + `/worklog/list`, both present in the WADL.
3. **Epic membership is preserved, not modelled.** Epics sync as tickets (interfaces §4.2 declares exactly one kind). The epic→child relation stays in `payload` — via `fields.parent` where the instance populates it, and via the optional `epic_link_field` config for classic DC projects — because discovering the Epic Link custom field id automatically needs `GET /rest/api/2/field`, outside M1's endpoint set. Turning it into a `knobas.link` row is M2.
4. **`expand=renderedFields` is not requested**, although interfaces §4.2 lists it among the search parameters. Reason: it returns HTML, and gotcha 7 is about HTML reaching the webview; REST v2 wiki markup is better FTS input and safe for the §3a generic detail view. Adding it later changes nothing structural. Confirmation wanted (open question 5).
5. **`GET /rest/api/2/issue/{key}` is not called.** `/search` already returns `fields`, so a per-issue GET would be an N+1 for nothing. Using fewer endpoints than the allowlist permits is safe — mockd only records *unknown* requests. The endpoint stays in mockd's set for M2's write-back re-read.
6. **An issue edited twice within the same second inside the overlap window is not re-delivered** (the `seen` set keys on `(key, updated)`, and Jira reports `updated` to the second). The item was already upserted once; the next distinct edit brings it back. Documented on `JiraCursor::already_delivered`.
7. **Beyond 500 issues sharing one 2-minute overlap window**, the cap on `seen` allows re-delivery. Upserts are idempotent, so the cost is bandwidth.
8. **429 after the retry budget is `Protocol`**, not a dedicated state — interfaces §4.1 says "anything else → Protocol". The message names `rate_per_sec` so the user can act.
9. **`knobas-http`'s exact API is assumed, not read** (open question 1). Task 2 Step 1 makes reading it the first action, and the adaptation is confined to one call plus `classify_transport`; the §4.1-sanctioned fallback is written out in full so the task is executable if the contract PR has not landed. The fallback drops the governor rate limit, which the swap restores.
10. **Task 7 is hard-blocked on stream T.** Tasks 1–6 carry the whole adapter with unit-level coverage of every algorithm; Task 7 adds the wire.

### Open questions for the orchestrator

1. **`knobas-http` (P8): publish its exported surface** — builder name, config struct fields, and whether it already exports status/transport classifiers. One paragraph unblocks Task 2 without guessing.
2. **Where does `ConnectionInfo` live** — `knobas_source::ConnectionInfo` (assumed) or `knobas_source::instance::ConnectionInfo`?
3. **For stream T, three things this adapter's requests depend on:** (a) how a test obtains the credential mockd accepts (`knobas_mockd::JIRA_TOKEN` assumed); (b) that the JQL subset parses the literal form this adapter emits — `updated >= "YYYY-MM-DD HH:MM"` — and a where-less full-sync query, `ORDER BY updated ASC` alone; (c) whether `/search` honours `fields=comment,worklog` (the adapter works either way — an absent container is treated as truncated and fetched — but the "no refetch" path is only exercised if it does).

The adapter tolerates a missing `updated` — the item syncs with `updated_at: None` and never advances the watermark — but an epic that never appears in an incremental result is worth knowing about.
