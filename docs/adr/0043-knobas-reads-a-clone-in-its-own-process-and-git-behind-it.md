# knobas reads a clone in its own process, and git behind it

Amends [ADR-0021](0021-knobas-reads-a-checkouts-state-with-read-only-git.md), [ADR-0026](0026-knobas-reads-a-checkouts-uncommitted-diff.md), [ADR-0036](0036-knobas-reads-any-diff-at-a-checkout-that-holds-both-commits.md) and [ADR-0041](0041-knobas-reads-a-branchs-tree-at-its-checkout-and-fetches-its-tip-there.md).

Every read of a checkout started `git`: a folder two processes, a file one, a commit four in a row, a compare fourteen. A start is a few milliseconds on a Mac and tens of milliseconds on Windows, where Björn uses knobas, so pages that were fast on the Mac missed their lines there by the starts alone (measured with each start held 100 ms: a commit 860 to 1,207 ms where the line is 100 to 300). Björn ruled the same day that knobas stays a native Windows app with no backend in WSL, so the starts could not be moved to where they are cheap. Decided 2026-11-16 (Fable, under Björn's standing instruction "Directness, performance, responsiveness over data scarcity"; `docs/decisions/2026-11-16-a-clone-is-read-in-process.md` has the measurements): **what a clone's commits hold is read in knobas's own process, and `git` is started for a read only where that reader says it cannot answer exactly.**

- **The reads** (`knobas_app::checkout::reader`, over the crate `knobas-git`): a commit resolved (`rev-parse --verify <sha>^{commit}`), whether the clone is shallow, a merge base, a commit's whole tree (`ls-tree -r -t -z --long`), a file's bytes (`cat-file blob`), the commits between two (`log`), and the diff between two commits as its names (`diff --raw`), its names with counts (`--raw --numstat`) and its patch, whole or for named files, with `-w` or without. These are every read ADR-0036 and ADR-0041 name.
- **The contract is git's own bytes.** Each read answers what the one command line prints, byte for byte, so the callers keep their parsers and a test compares the two outputs. `knobas-git` is gitoxide (`gix`, pure Rust, MIT or Apache-2.0) for the object database, revisions and merge bases, its line differ (`gix-imara-diff`) for hunks, and its own code for what gitoxide does not print as git does: the walk of `log`, the rename pairing and its score, the patch and its headers, abbreviations.
- **git stays the reference.** A read the reader does not reproduce exactly is handed back (`AskGit`), and the command runs as before under ADR-0036's environment: a repository it cannot open (another owner, which git refuses too; SHA-256; a grafts file), a shallow clone's history, a short sha that is also a ref's name, a blob past 64 MiB, a `diff.algorithm` other than Myers, `diff.indentHeuristic` off, `diff.context` of 0, an order file, `diff.relative`, `diff.suppressBlankEmpty`, `diff.submodule` other than `short`, `core.abbrev` other than `auto`, a named diff driver (`diff=<name>`) on a changed path, `GIT_DIFF_OPTS`, `log.showSignature`, a commit with an `encoding` header. It follows `diff.context`, `diff.interHunkContext`, `diff.renameLimit`, `core.quotePath` and the `diff`, `-diff` and `binary` attributes.
- **ADR-0021's and ADR-0036's terms hold by construction.** The reader has no write and no transport: it refreshes no index, takes no lock, fetches no missing object, follows no replace ref, opens the repository at the path and no higher, reads no `GIT_*` variable, and starts no process (gitoxide is told not to ask the git binary where its configuration is; the system file is found beside the `git` on `PATH`). Names are checked shas, as before.
- **The working tree stays git's.** The working tree state (`status`, ADR-0021) and the uncommitted diff (ADR-0026) depend on the person's clean and smudge filters, line-ending settings, sparse rules, ignore files and submodules, which only their git applies as they see it in a terminal. What changed is when git runs: the stamp that says nothing changed (ADR-0021 as amended 2026-11-10) reads Windows's file metadata too, where it gave up and every view started `git status`; the uncommitted diff is kept by the same stamp; its three commands run at once.
- **The writes stay git's**: `clone`, the fetch of a tip (ADR-0041), `worktree add` (ADR-0035). None is a wait a press makes.
- **A repository is held open twenty seconds** after its last read, eight at most. An open repository holds its pack files mapped, and on Windows a mapped file cannot be deleted, so a `git gc` in a terminal would leave old packs behind while knobas held them.
- **The way back is a switch.** `KNOBAS_CLONE_READER=git` in the app's environment has every read here start `git` as before this ADR (`checkout::reader::READER_SWITCH`). It is how the two are compared in the app itself with one build, on a machine nobody builds on, and what to set should a clone ever read wrong in-process.

## Rejected

- **libgit2 (`git2`).** A C library on three platforms, with xdiff (LGPL-2.1) inside. It runs no external filter and pairs renames by its own measure, so the two places an in-process reader is hard, working trees and rename scores, would be no closer to git than gitoxide's.
- **A long-lived `git cat-file --batch` and `git diff-tree --stdin` per clone.** Exact by construction, but the first read after a pause is still a start, a diff of named files needs `git diff-pairs` (git 2.50), each set of flags is a process of its own, and a process whose working directory is the clone keeps Windows from renaming or deleting the folder.
- **Reading from the mirror's stored trees** (the stored-trees pass). They hold the tips' folders, not file contents or history, and the clone is already on the disk.
- **The working tree in-process.** gitoxide reads a status, but not provably as the person's git does with their filters, and a wrong "3 changed" is worse than a late one.
- **A gitoxide diff as it is.** Its unified diff writes `@@ -a,b +c,d @@` with no function line and always both counts, and its rename tracker measures how alike two files are its own way, where a list and a patch have to say git's score to the digit.

## Consequences

- A folder, a file, a branch switch, a commit, a compare and a pull request's *Files changed* at a clone start no process. The first open of *Local changes* after a change in the working tree starts three at once, and a view of a checkout whose working tree changed starts one `git status`.
- A machine without git reads a clone's files, commits and diffs; only the working tree's state says *git not found*.
- An answer may now come from two programs, so their agreement is tested, not assumed: `crates/knobas-git/tests/it` compares every read with the `git` on `PATH` over fixtures of each edge case, `examples/parity.rs` over a real repository's history, and `just git-starts` fails when a press at a clone starts git.
- gitoxide is 65 crates in the lockfile and 3.6 MB of the binary. A gitoxide release may change what it prints; the parity tests are what an upgrade runs.
- The rename pairing, the similarity measure, the walk and the patch writer are knobas's own code written to give git's output. They follow git's algorithms and copy none of its source.
