# External links hand off through Firefox Native Messaging and a custom scheme, with a one-shot bypass

Extends [ADR-0050](0050-a-sources-site-is-a-web-view-of-its-own-with-no-way-into-knobas.md) (embedded source sites) and stands beside the paste resolver (`knobas_core::web_url` and `knobas_source::url_forms::UrlForm`). Clicking a Jira ticket, Confluence page, TeamCity run, or Gitea pull request in chat or Firefox leaves the reader in the browser even when knobas already mirrors that item. Decided 2026-11-26 (spec #2514, #2530): **any configured source may opt into *Open matching links in knobas* — defaulting to *Known items only* with an optional *Whole source* mode — delivered through an OS `knobas://open?url=...` scheme and a Firefox Native Messaging stdio host talking to the running knobas instance over an authenticated local bridge, with a short-lived one-shot bypass recorded whenever knobas opens a URL in the browser.**

- **Per-source opt-in and scope.** Stored in `knobas.setting` under `link_handoff.source.<source_id>` (no migration; removed when a source is deleted). Off until a person turns it on. Default scope is `known_items` (*Known items only*): only URLs that resolve through `resolve_url_inner` (`sync.item.web_url` and declared `UrlForm` templates) open their native knobas view; everything else stays in the browser. Optional scope is `whole_source` (*Whole source*): non-entity URLs under the source's base URL route to that source's embedded site when *Open its pages inside knobas* is on (ADR-0050), and stay in the browser when it is off.
- **No adapter changes and one URL rule.** `crates/knobas-source/**` is untouched. URL resolution remains `resolve_url_inner`, and URL normalization for bypass keys and base-URL prefix matching follows `web_url_normalized!`: `http` and `https` only, lowercase `scheme://host[:port]`, `#fragment` stripped, trailing `/` stripped from the path, `?query` kept verbatim. When two enabled sources share a host, the longest segment-boundary base path wins.
- **Custom scheme `knobas://open?url=<encoded>`.** Registered at bundle/install time via `tauri-plugin-deep-link` (Rust-only, pinned exactly, no npm half, no capability grant). On macOS, warm and cold open-URL events arrive via `on_open_url`; on Windows and Linux, a second launch's `argv` is forwarded by `tauri-plugin-single-instance` and cold-start `argv` is queued in `LinkHandoffState` until both PostgreSQL and the webview (`frontend_ready`) are ready. Only `knobas://open?url=<http(s)>` is accepted; every other scheme, action, or non-`http(s)` target is refused and logged.
- **Firefox Native Messaging stdio host.** The main `knobas` executable serves the Native Messaging stdio loop (4-byte unsigned little-endian length prefix + UTF-8 JSON, capped at 1 MiB) before Tauri initializes when invoked as `native-messaging-host` or with Firefox's standard `<manifest.json> <extension-id>` arguments. Host name: `dev.knobas.desktop`. Allowed add-on ID: `link-handoff@knobas.dev`. Manifest registration is managed per user on macOS (`~/Library/Application Support/Mozilla/NativeMessagingHosts/dev.knobas.desktop.json`) and Windows (`%APPDATA%\dev.knobas.desktop\native-messaging\dev.knobas.desktop.json` referenced by `HKCU\Software\Mozilla\NativeMessagingHosts\dev.knobas.desktop`).
- **Authenticated local bridge to the running app.** The running knobas instance listens on a user-only `0o600` Unix domain socket (macOS/Linux) or loopback TCP `127.0.0.1:0` (Windows) and writes `<profile_dir>/link-handoff.json` (`0o600` on Unix) holding the transport address and a per-session random bearer token (two v4 UUIDs, 244 random bits), removed on quit. The short-lived Native Messaging host forwards requests over that bridge; if knobas is not running, `ping` reports `running: false` and other calls return `knobas_not_running` so Firefox loads the page normally with zero prompts.
- **One-shot *Open in browser* bypass.** Every browser open in the app passes through `app/src/lib/shell/open-external.ts` (enforced by `house-rules.test.ts`). Before calling `openUrl`, `openExternal` invokes `record_browser_bypass(url)` (best-effort, never blocking the browser open on bridge failure). The backend stores a 15-second one-shot pass (capped at 128 live entries) in memory; the next Native Messaging `check_bypass` or `handoff` for that normalized URL consumes it and tells Firefox to let the tab load normally, preventing redirect loops without weakening subsequent clicks on the same link.

## Rejected

- **Triggering `knobas://` redirects directly from the Firefox extension.** Firefox shows an external-protocol confirmation dialog on custom scheme navigations and cannot tell whether knobas is running or whether a URL is a mirrored item before opening a prompt. Native Messaging gives zero-prompt handoff and clean fallback.
- **A separate helper binary or shell wrapper script for Native Messaging.** A shell/batch wrapper flashes a console window on Windows and adds quoting bugs; a second binary doubles signing/notarization work. Dispatching before Tauri initializes in `main.rs` follows `file_pipeline::main_if_asked` and `live_sources::main_if_asked`.
- **Re-implementing SQL URL resolution inside the browser extension.** Only knobas holds PostgreSQL `sync.item.web_url` and payload fields for `UrlForm`. The extension pre-filters on enabled source `base_url` prefixes and asks knobas's `handoff` endpoint for the authoritative decision.
- **Persisting one-shot bypasses to PostgreSQL or disk.** Bypasses live 15 seconds for the active session only; an in-memory map avoids database writes on every *Open in browser* click.

## Consequences

- `tauri-plugin-deep-link = "=2.4.10"` joins `crates/knobas-app/Cargo.toml` (Rust-only, pinned in `tests/it/wiring.rs`) and `plugins.deep-link.desktop.schemes = ["knobas"]` joins `tauri.conf.json`. `capabilities/default.json` and `app/package.json` gain nothing.
- The frozen IPC surface grows additively by six commands in `commands/app.rs` (`source_link_handoff`, `set_source_link_handoff`, `firefox_host_status`, `install_firefox_host`, `uninstall_firefox_host`, `record_browser_bypass`) and one event (`link-handoff:open`, payload `LinkHandoffTarget`), mirrored in `app/src/lib/ipc/app.ts` and `app/src/lib/ipc/index.ts`. No migration and no `crates/knobas-source` changes.
- `CONTEXT.md` gains **Link handoff**.
- Windows HKCU registry registration and OS `knobas://` association behavior are compile-checked under `#[cfg(target_os = "windows")]` and owed a live Windows milestone witness.
