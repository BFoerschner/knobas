# Text search reads the tree the Files tab shows, live, beside the files index

Stands beside [ADR-0048](0048-a-repositorys-files-are-indexed-outside-postgresql.md)'s files index, reads a branch where [ADR-0041](0041-knobas-reads-a-branchs-tree-at-its-checkout-and-fetches-its-tip-there.md) reads its tree, in process as [ADR-0043](0043-knobas-reads-a-clone-in-its-own-process-and-git-behind-it.md) reads a clone, with git only reading ([ADR-0021](0021-knobas-reads-a-checkouts-state-with-read-only-git.md)) and nothing of the mirror on its command line ([ADR-0016](0016-a-spawned-command-takes-no-argument-from-the-mirror.md)), and reads the working tree as [ADR-0049](0049-a-comparison-may-end-at-the-working-tree.md)'s comparisons do. Decided 2026-11-26 (spec #2514, #2522): **a repository's Files tab searches the text of its files ripgrep's way (every line holding a literal or a pattern, smart case), live, in the very tree the tab shows: the clone's copy of the branch's commit, read in knobas's own process; the working tree on disk as git lists it; and only where no clone holds the default branch, the files index's copy of it, said so on the answer. A branch no clone holds and the index does not read is not searched.**

- **One command, three places.** `entity_text_search` (`commands/entity/checkouts.rs`, behaviour in `checkout/text_search.rs`) takes the tab's entity (the repository or a branch), the commit the tab reads at (the mirror's tip where it has none), whether the working tree is chosen, the branch's name and the query (`TextQuery`: the text, *Aa*, *.\**, and whether file names are asked too). It answers `TextFound`: where the lines came from (`clone`, `working_tree`, `index` or `none` with the reason), the commit or the index's branch, each file with its first 20 lines and how many more, the names, how many files were read and skipped, and whether the search was cut.
- **A branch in a clone.** The tree is the one *Files* already keeps for the commit (`checkout::local::tree`), and each blob is read by the sha that tree kept, through `knobas-git` in process, on up to eight threads each with its own repository handle. Nothing is checked out, nothing is written, and a path never reaches git. A blob `knobas-git` cannot answer is read by git, as every other read of a clone.
- **The working tree.** The files are those git lists there, tracked or untracked and not ignored (`working::listing`: the index and `git status --untracked-files=all`), the list the tab's `M`/`A` marks come from, so `.gitignore`, `.git/info/exclude` and the global excludes are read by git itself and never re-implemented. Each is read from disk as it is now, never through a link; a link and a submodule are not searched.
- **No clone.** The files index keeps the text of every repository's default branch. Its stored text is scanned line by line with the same matcher (`FileIndex::each_text`), not asked through the index's words: a literal is found inside a word (`retry` in `preretry`) and a pattern means what it says, as in a clone. It is the default branch's copy as of the last sync, and the answer says so.
- **Bounds.** A search stops at 500 lines shown; a file over 2 MiB, and a file with a NUL in its first 8,000 bytes (git's own binary sniff), is skipped and counted. The threads take the files in path order and finish each one they took, so a cut answer is the first 500 lines in path order every time. A newer search of the same tab's tree (its repository or branch) stops the scan before it; each search takes its turn when it is asked, before anything is read, so an older one never stops a newer one. The page drops an answer that lands after a newer question, and asks once more when its newest question was stopped by another tab's search.
- **Matching.** Smart case by default: a query with an upper-case letter of its own matches its case, one without matches every case (in a pattern, a letter after `\` is the syntax's). *Aa* matches the case typed. *.\** reads the text as a Rust `regex` pattern; one that does not parse is answered with why. A match never spans a line.
- **The page.** The Files tree's search box is *Files* (*Go to file*, `T`) or *Text* (`Mod+Shift+F`, from anywhere on the tab, a field included), a segmented control above the field, with *Aa* and *.\** as pill toggles beside the field. The answer stands in the tree's place: each file a row with its count, its lines under it with their numbers and the hits marked; a file opens at its top, a line at that line. *Search in repository* on selected code (a repository's file view, or a pull request's, a compare's or a commit's diff) opens that repository's Files tab on *Text* with the words, and asks for file names too.

## Rejected

- **Asking the files index for every search.** It holds the default branch only, as of the last sync, and finds words, not text: a search on a feature branch, on the working tree or for a part of a word would answer something other than what the tab shows.
- **`git grep`.** It starts a process per search, which ADR-0043 retired from every read of a clone, and on the working tree it reads what the index holds, not what is on disk.
- **The `ignore` crate for the working tree.** A second reading of `.gitignore` beside git's own would disagree with the tab's marks wherever git's rules and the crate's differ (`core.excludesFile`, negations under ignored folders); the list git gives is the one the tab already draws.
- **Searching a branch no clone holds through the forge.** No forge in knobas's adapters offers a code search that is faithful to one branch's commit, and reading every file of a branch from the forge per search is not live. Such a branch says *Clone this repository to search this branch*.

## Consequences

- The frozen IPC surface grows additively by one command, `entity_text_search`, and the types `TextQuery`, `TextFound`, `TextFile`, `TextHit`, `TextPart` and `TextFrom`, generated into `generated/entity.ts` and wrapped in `app/src/lib/ipc/entity.ts` (`docs/contract.md`). No migration. `knobas-files` gains `FileIndex::each_text`; `knobas-search` is untouched.
- `CONTEXT.md` gains **Text search**.
