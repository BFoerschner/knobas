# A folder renderer is given a copy of the folder knobas wrote

*Amended by [ADR-0049](0049-a-comparison-may-end-at-the-working-tree.md) (2026-11-20): a copy of a working folder, made of what git lists.*

Amended by [ADR-0046](0046-a-folder-renderer-may-make-a-folder-of-files-knobas-keeps.md): a folder renderer may be given a third path, {outdir}, and make a folder of files.

Amends [ADR-0016](0016-a-spawned-command-takes-no-argument-from-the-mirror.md) and [ADR-0033](0033-renderer-and-pipeline-commands-run-under-the-rules-of-open-in.md). Björn, on PR #2479 (ux17): "I want to be able to render a folder. Because I might want to build a tool that takes a path to the folder and outputs a png, a text, or anything. Because the lowcode tool takes a folder and its contents and generates something out of it." A file renderer reads one file on stdin; a folder is many files, and a tool like that takes a path. Decided 2026-11-16 (Fable, xhigh, under Björn's standing instruction; `docs/decisions/2026-11-16-a-folder-is-drawn-by-a-tool-of-your-own.md`): **a folder renderer is set up like a file renderer, and is given two paths knobas made: `{path}`, a copy of the folder that knobas wrote, and `{out}`, a file to write to.**

- **Two placeholders and no others.** The program and its arguments are what the person typed in Settings › Renderers › *Folder renderers*, split as ADR-0033 splits them, no shell. `{path}` is required; `{out}` is optional and may have text after it (`{out}.png`). Save refuses any other `{name}`, `{branch}` or `{sha}`, naming it. ADR-0033 rejected a path placeholder because a template language invites mirrored values as arguments; these two name only paths knobas made, so the rule ADR-0016 guards still holds.
- **The copy, never the checkout.** knobas writes the folder at the commit the Code page shows into a fresh folder under the system temp directory (`knobas-fr/`), from the clone's git objects where the clone holds that commit, else from the forge. The working folder is not given: a tool that writes into the folder it reads would write into the working tree, which ADR-0016 forbids, and a copy of a working folder needs git's ignore rules and filters, which ADR-0043 leaves to git. The copy holds what git holds: LFS files are their pointers, a symlink is a file holding its target, a submodule an empty folder; an executable file keeps its bit on Unix.
- **The copy's name.** It is the folder's own last segment when that is a plain name (`[A-Za-z0-9][A-Za-z0-9._-]{0,63}`, not ending in a dot, not a Windows device name), as ADR-0034 passes a branch name once checked, else `folder`. A tool that names a project after its folder sees the project's name.
- **File names on disk are data, as stdin is.** Every path of the folder is checked before the first write, and the copy is refused, naming the path, for `..`, an absolute path, a backslash, a colon, a character Windows refuses, a control character, a device name, a name ending in a dot or a space, or two names of one folder alike but for case. The same rules hold on every platform.
- **Where it runs.** In an empty folder of its own, not the copy: on Windows a program's children are looked for in the current directory before `PATH`, so a mirrored `git.exe` in the folder would run. A person who wants to start in the folder types `sh -c "cd '{path}' && …"` or `cmd /c "cd /d {path} && …"`, and Settings shows the recipe. Stdin is closed. The environment is the parent's less every `KNOBAS_*` variable, under `knobas_db::console`.
- **Limits.** The output (the one file under `{out}`, else stdout) is refused past 64 MiB; stderr is kept to 64 KiB. The timeout is 1 to 600 s, 30 s unless set, and does not count the copy. At the timeout, a stop or the app's quit the program is killed with everything it started: its process group on Unix, its process tree (`taskkill /T /F`) on Windows. A copy from the clone holds at most 20,000 files and 1 GiB; one from the forge 1,000 files and 64 MiB, checked against the listing before any file is read.
- **What comes back is untrusted**, as ADR-0033 says: HTML is sanitized and drawn in a frame with `sandbox=""`, served from the render scheme by a token under the file renderers' policy (no script, no request). Images and text travel as raw bytes, never as a data URL in JSON.
- **It runs only when a person opens it.** A run starts on the shown page's open or *Run again*; a kept or prebuilt page, a hover or a sync starts nothing.

## Rejected

- **Running in the checkout's folder.** Fast and it sees uncommitted changes, but the tool may write into the working tree, and the folder's mirrored files would be the program's current directory.
- **A copy of the working folder.** It needs git's ignores and filters to be what the person sees (else `node_modules` is copied), which only their git applies; a later pass may add it beside the commit's.
- **Scripts in a folder render's page.** A page a generator wrote can hold anything it read on this disk, and `connect-src 'none'` does not stop a script setting `location`. A scripted page needs a nested frame whose own policy names only the render scheme, witnessed on WebView2 and WKWebView; until then a page runs no script.
- **A placeholder for the folder's path in the repository, its branch or its commit.** Mirrored values as arguments, which ADR-0016 forbids.

## Consequences

- The witness is the real programs at the seam: `crates/knobas-app/tests/it/folder_render.rs` (a real clone, a folder copied at the commit and listed by `sh`, the same folder at a later commit drawn at once, a refused name before the program runs) and `folder_render::runs`' tests (a printing tool, one writing `{out}.png`, a failure kept for the session, a timeout, a stop, one run per folder, the disk cache over a restart, the queue). The sanitizer and the frame are witnessed in vitest (`TfFolderRender.test.svelte.ts`).
- The drawings are kept by the folder's content: from the clone every path, mode and blob under it, so the same folder at another commit is the same drawing; from the forge, which names no blob, the commit and the folder. In memory (128 MiB) and on disk under the profile's `folder-renders/`, one folder per source (512 MiB), removed with its source or a new credential. A backup dumps the database and never carries them. Not a database table: a migration is a frozen surface, and files are what the drawings are.
