# A page shows what knobas last read, and reads the source behind it

Amends [ADR-0032](0032-the-app-keeps-live-reads-in-memory-keyed-by-what-they-stand-at.md) and extends [ADR-0041](0041-knobas-reads-a-branchs-tree-at-its-checkout-and-fetches-its-tip-there.md) past *Files* and *New pull request*. Decided 2026-11-09 (Björn, on PR #2479: "I want the app to be smooth at all times", "see if that problem also persists on other sources like docs, tickets etc."). Measured before and after on PR #2479 through a proxy holding every request to the testenv products 1 s, 5 s, forever, or refusing it (`crates/knobas-app/tests/slow_sources_live.rs`, `slow_forge_live.rs`).

*Amended 2026-11-13 (the compare pass of PR #2479): Compare's *Commits* are the compare's own, from the clone's `git log` or the source's compare, wherever its read lists them, so they draw with the list of files; the branch's view, a read of seconds on the forge for a branch knobas never read, is what they fall back on. Without a clone, a compare of two branch names is the source's answer now, as before: it is not held, since a branch name moves, and its list of files is all that reaches the page.*

*Amended 2026-11-13, the forge-waits pass (`docs/decisions/2026-11-13-a-file-after-a-sync-and-a-first-compare-wait-on-nothing.md`), reversing the line above for lists: a compare's list of files between two branch names is held (`range_files:<base>...<head>` of the repository) and answered at once with `held_at` (`RangeFiles.held_at`, additive), drawn under the held line and checked behind by the source's list; a different answer replaces it in place, quietly. The whole diff is held under the two shas the source settled (`range_diff:<base>...<head>`, fixed) where it fits a row. Without a clone, the repository page asks *New pull request*'s list once its landing drew, and a compare whose link the pointer rests on, once a session each, and Compare takes that read. A file drawn at a commit before its tree's (a sync moved the branch) stays drawn, undimmed, with the held line in its header's meta, and is replaced in place when the clone or the source answers.*

*Amended 2026-11-13 (the big-folder pass of PR #2479): a page's first answer is what knobas last read, so after a push *Files* first draws the tree at the commit before. A page that compares that answer with something else (the checkout's tree, ADR-0041) compares the read behind it as well: *Files* takes the commit of every read of its top, so the clone's tree, fetched to the new commit, takes over once both stand at it.*

*Amended 2026-11-14, the stored-trees pass (`docs/decisions/2026-11-14-every-branchs-tree-is-stored.md`): for a branch's or repository's tree, a [stored tree](../../CONTEXT.md#stored-tree) answers before the held reads, where the sync read the branch at the commit the page reads; a read held since that is newer still wins. The rejection of *Prefetch views after each sync* below stands for views; a tree is stored because it is git's own shape: a directory two branches share is one row, only the directories the store lacks are read, a branch that did not move costs nothing, and the requests are bounded per run and wait behind a person's (the priority lane).*

*Amended 2026-11-15, the forge-rounds pass (`docs/decisions/2026-11-15-first-opens-without-the-forge.md`): a section of a branch's or repository's tree that reads the branch's head and was never read (the landing's README, a deep link's folder or file) is read at the commit the mirror holds at that head (`Source::tip_branch`, `Source::view_at_tip`, optional SPI methods), one round of the forge where learning the tip took two more, drawn as of the sync that saw it and read behind, never held; after the stored tree and the held reads, before the source. A default branch's README is stored by its blob (migration `0090`) and drawn with the stored tree. *Prefetch views after each sync* stays rejected; holding each open pull request's *Files* after a run is owed as its own pass, under the conditions that note sets.*

*Amended 2026-11-15, the held-files pass (`docs/decisions/2026-11-15-the-files-a-pull-request-opens-are-held.md`), the first amendment of *Prefetch views after each sync* below, for one view: after each run of a source whose adapter names a held shape (`Source::held_shape`, an optional SPI method), the sync reads the section it names of each record the mirror holds open whose two commits, or whose count of line comments, moved since the held copy (Gitea: each open pull request's *Files*, whose diff stands at its merge base and head; its `review_comments`), through `Source::view`, the page's own read, and holds it in `sync.held_read` as a **speculative** row (migration `0092`). A page's first open of *Files changed* draws it at once under the held line and reads behind, as any held read; a thread the read behind brings is replaced in place, the line the reader is on kept where it was. The pass sends at most 200 requests in 45 s a run, in the background lane; an unchanged run asks nothing and writes nothing; its rows fill at most half the store and leave first when the store is full, until a page draws one; a record no longer open drops its row; a record the forge failed on goes last in the runs after. A *Files* row may be up to 8 MiB, whoever writes it, so a pull request of thousands of files is held too; every other read stays at 2 MiB, and the rows over 2 MiB take at most half the pass's share. The rejection stands for every other view.*

**A page that draws a [source view](../../CONTEXT.md#source-view) or a source read answers from what knobas last read whenever it holds one, says from when, and reads the source behind it.** Only a read knobas has never made waits for the source, and then without blocking anything else on the page.

- **Where the answer comes from, in order.** The [read cache](../../CONTEXT.md#read-cache) in memory; then **held reads**, `sync.held_read`, what a page read in an earlier session; then, for a view never read, what the adapter can draw from the mirror's own record of the entity (`Source::mirror_view`, an optional SPI method, `None` by default: Gitea draws a pull request's overview and *Files* count from it); then what it can draw from the records of the entities under it (`Source::mirror_listing`, amended 2026-11-12 below: a repository's branches and its last commit); and only then the source, waited for.
- **Live views are kept too, for pages.** ADR-0032's *Live* standing meant "never kept". A page's read (`entity_view`) of a live view is now kept and held like a moving one, answered at once and read again behind. Internal reads that need the source's word now (a compare's check, a range diff) still read it.
- **Fixed reads are held between sessions too**, and never read behind: a view at a whole sha, a finished run's log, tests, artifacts and previews (the mirror's declared `finished` says so), an attachment's bytes by its content address.
- **Moving reads other than views** take the same path: a pipeline's settings (*Run…*'s parameters, and the commit a shared sha resolves to on Builds, which waited up to 5 s on them).
- **The page's read of what it was told is not read behind again** (amended 2026-11-15, `docs/decisions/2026-11-15-a-persons-read-beside-a-running-sync.md`): within five seconds of a tell (`ECHO_WINDOW`), a page's read of that view is answered from the answer just read, once; before, each tell cost a second read of the forge.
- **The page is told how the read behind went** (`view:fresh`): when the answer moved, as before; and, for an answer older than `HELD_AFTER` (30 s), when it was confirmed or when the source failed, with the failure. The page draws one quiet line over what it holds (*As knobas read it 2 h ago. Checking Tidewater Git…*, or *… Tidewater Git did not answer: …*), and drops it when the fresh answer lands. A failure re-reads nothing.
- **A read that fails with nothing held** is the page's error as before, unless the page holds something of its own to draw: a commit's page draws the mirror's row and the clone's diff and leaves out only the parent and *New branch from here…*; Compare draws the clone's diff and leaves out the branch's standing; a pull request's *Files* draws the clone's diff between its two branches while the source's is out, said to be so, without threads.
- **Grants move.** Jira's, Confluence's and TeamCity's grants are moving, as Gitea's were: answered from memory and asked again behind. *Amended 2026-11-15 (`docs/decisions/2026-11-15-a-persons-read-beside-a-running-sync.md`): asked again behind only once the kept answer is a minute old (`GRANTS_FRESH`; Gitea's are two probes on the forge an ask), and dropped at once when a write of the source is refused, as on a new credential.* They stay in memory: a write is drawn as allowed until its grant answers, and a grant knobas could not ask still refuses (#2306).
- **Bounded, and gone with what read it.** `sync.held_read` holds 64 MiB, the oldest reads going first, and never a read over 2 MiB. *(Amended 2026-11-15, the held-files pass: a pull request's *Files* up to 8 MiB; the rows the sync held that no page drew go first.)* A row is keyed by what the source was built from short of its credential (adapter, address, method, configuration), so an edited source answers none of its old reads; a new credential deletes them, and removing the source deletes them by the foreign key. It sits in `sync` beside the mirror, so a backup, which dumps the `knobas` schema, never carries one.

## A kept page reads again on its return (amended 2026-11-10)

The third smoothness pass of PR #2479, found in the app's own window: a repository page kept open did not read its branch list again on its return, so a branch made after it first drew was unknown to Compare, *New pull request* and the header until a refresh (Björn: "fix that, I don't like this behaviour").

- **When.** A repository page reads its branch list and its pull requests again, each through this ADR's path (at once from what knobas holds, the source behind it), when it is shown again, when another of its tabs is shown, when the window comes back after `HELD_AFTER` or more, when a branch knobas made lands, and when a run of its source ends with something new (amended 2026-11-15, `docs/decisions/2026-11-15-a-persons-read-beside-a-running-sync.md`: every run's end read the branch list and its grants again, 17 requests to the forge a minute on a page left open; a run that changed nothing now reads nothing, and one that ends while the window is hidden is read once on its return). A role view reads again when a run of a source filling its role ends with something new while it is shown (`RoleSync::ran`), or its *Sync now* ends; hidden, it reads once on its return if either happened meanwhile, and a return to what nothing changed reads nothing (amended again 2026-11-10, the fourth pass: every return read the whole view, at Björn's size Code's 79 reads and 860 KB). Code's checkouts are read on each return all the same, because a commit or a clone in a terminal changes them and no sync brings that.
- **A row the mirror has not synced is readable, never linkable.** ADR-0020 rule 7 still clears such a row's `entity_id`, so it links nowhere. `entity_view` now answers beside the view each row it cleared, with the id the adapter named for it (`ShownView.unsynced`: section, title, id; additive, absent when empty). The repository page offers a branch so listed, and reads its view, its files and its commits at that id through the source, as it reads any branch; it offers no write that needs the mirror (*Delete…*) until a sync holds it.
- **A branch knobas made is offered at once**, from its echo (`MADE`), until a read lists it.
- **Not found is the source's word, and only after every read that could find it.** Compare reads a branch the list lacks by name; a 404 of the source's compare is `not_found`, and the page says the branch is missing only then and while no read of the list is running.
- **What the reader is on does not move.** A list read again keeps the first row on screen where it was and focus where it was (`landInPlace`).

## A page's reads of the mirror are kept in the window too (amended 2026-11-12)

Björn, on PR #2479: "it's fast after the first load. but some sites take some time to load again. Since everything is inside the mirror it should be instant." A page the kept pages dropped, and the first open of a page, waited for the backend again: Docs 777 ms, Builds 296, Code 247, Tickets 130 at the saved scale database (`docs/decisions/2026-11-12-opening-a-page-draws-what-the-mirror-holds.md`).

- **What this ADR does for a source's views, the window does for the mirror's answers.** The [answer cache](../../CONTEXT.md#answer-cache) (`app/src/lib/ipc/answer-cache.ts`) keeps the last answer to each read that is a function of the mirror and the settings, so a page mounted again draws from memory in the frame after the press, and reads nothing it would read the same.
- **It never answers what the mirror no longer holds.** A run that changed something drops every answer a source of its roles could change, and a write, a refresh of an item, a held view that moved, a fetch landing, or the database going away drops every answer; a read on its way when answers were dropped is not kept. So the rule above for a kept page holds for a page mounted again: a return to what nothing changed reads nothing, and one after a run reads what the run changed.
- **Warmed.** After start, and after a run dropped answers, the reads the window made last are asked again in the background, one at a time, so a first open finds them.
- **Not for reads past the mirror.** A checkout's state, a source's view and a search go to the backend every time, as above.
- **Docs reads what it draws** rather than its whole tree (`docs_outline`, `docs_nodes`), and the backend keeps the tree it computed until a page's row moves (`docs::TreeCache`).

## The main sections are built ahead of their first press (amended 2026-11-15)

The ux13 Windows pass of PR #2479: Builds' first open drew in 282 ms at CPU 4x and 415 at 6x in knobas's window on Björn's PC, the Tickets board's in 202 at 4x, every return within its line. On the Mac a first open cost about twice a later mount of the same page, the engine running the page's code and working out its styles for the first time (`docs/decisions/2026-11-15-whats-over-on-the-pc-with-ux13.md`). Ruled by Fable, the pass's one decision agent, for Björn.

- **Once the window is ready**, the shell opens Tickets, Builds, Code, Monitors, Inbox and Docs hidden, one at a time, each after a second with no key, press, pointer move, wheel or scroll and an idle moment (`app/src/lib/tf/ahead.ts`), at the address its nav entry goes to then, never the section shown. Each goes into a free room of *Pages kept open*, behind every page held, so it never drops a page the reader left, a later visit drops it first, and 0 opens none; the setting's words say so.
- **A page held ahead is a kept page** in every other way: it reads what it draws, through the [answer cache](../../CONTEXT.md#answer-cache), pauses while hidden, takes no keys and marks nothing read (a Jira view marked new waits to be shown); a role view held ahead re-reads on its first show only if a run of its role ended since it mounted. Its first press is a return.
- **Not taken:** warming each page's code off screen with made-up data (half the gain, made-up data per page, no page kept); one laid-out frame before a held page hides (measured: Builds' and the board's first show slower at 6x).

## A repository never opened draws its branches and last commit from the mirror (amended 2026-11-12)

The inner-pages pass of PR #2479 (Björn: "did you check the inner pages as well, when opening a repository itself etc? that took a long time too"), measured against the live Gitea through a proxy (`docs/decisions/2026-11-12-the-inner-pages-draw-what-knobas-holds.md`). A repository opened for the first time waited on the forge for its branch list, which the header's *Branch*, *New pull request*, Compare and the tabs' bookkeeping all wait for, and for its last commit, which kept the landing waiting under its skeleton: 2.8 s and 3.9 s on the first open after start, with the sync of that start loading the forge.

- **`Source::mirror_listing_kind` and `Source::mirror_listing`**, optional SPI methods, `None` by default (additive; announced under *Frozen surface* in PR #2479). The adapter names the kind of the entities under the entity whose records draw a section; the app reads those records, the live ones of the entity's source whose stored parents name it (the stored parents `EntityFilter.parent` reads), and hands them over with the entity's own record. Drawn as `mirror_view`'s are: kept, said to be as of the newest sync among them, read behind, never held.
- **Gitea** draws a repository's `branches` with the source's own rows over the branch records, in the source's order, so where nothing moved the source's answer lands on the same list; and its `commits` as the default branch's tip, the source's first row, with no count, the rest joining after it when the source answers. A repository the mirror holds no branch of draws nothing, not an empty list.
- **The held line keeps its room** once drawn: the words go when the fresh answer lands, the line's place stays, so the list under it does not move up.

## A read behind waits for a person's reads of the same server (amended 2026-11-17)

The ux16 Windows pass of PR #2479: Compare's first open on a repository without a clone took 485 / 669 / 430 ms at CPU 1x / 4x / 6x on Björn's PC, where Gitea answers its compare in 40 to 90 ms. A timing proxy in front of Gitea showed why: the branch's standing, drawn from what knobas held, was read again behind it at the same moment, eight requests (the repository, the branch, the open pull requests, the branch's compare of every commit with its files, the behind count, the statuses, all branches) on the server beside the compare's two, and the server answered them together (`docs/decisions/2026-11-17-a-page-s-waited-read-goes-first.md`). Ruled by Fable, the pass's one decision agent, for Björn.

- **A read behind runs in the background lane** (`knobas_http::behind`): its requests stand aside while a person's to the same server wait or are out, and 150 ms after, as the sync's do, and never more than a second at a time. Nobody waits on it; the page drew what knobas held and is told if the source moved.
- **Not after a person's write**: for 30 s after a write of theirs lands, the reads behind its repository's or item's views go as a person's, since they are what shows the write took.
- **A page may ask a view behind its waited read** (`entity_view`'s `behind`): Compare's branch standing and a commit's view, which only add to what the compare's list and the commit's diff draw. What knobas holds of them is answered at once as before.
- A pull request's first *Files* read made behind still keeps its diff for the next open (`knobas_http::is_behind`), as a page's own read does; the sync's, in the same lane, does not.
- Measured during a sync of the scale estate: a branch standing read behind Compare drew 0.9 to 1.1 s after the press, against 0.6 to 0.8 before; Fable's line is 2 s.

## Rejected

- **Keep ADR-0032's memory-only cache and add a skeleton.** Every restart made every page wait again; at a source 5 s away that is 15 s for a pull request or a run, on every first open of the day.
- **Prefetch views after each sync.** Thousands of requests a sync for pages nobody may open, and a source under load is the one that can least afford it. *(Amended 2026-11-15 for one view, above: each open pull request's *Files*, read only when its commits moved, capped a run and behind a person's reads.)*
- **Hold reads in the `knobas` schema.** A backup would carry another machine's reads of sources it may not reach, and a restore would answer pages from them.

## Consequences

- `ShownView` gains `unsynced` (additive; announced under *Frozen surface* in PR #2479). Witnessed by `entity_view.rs` (`a_pages_read_names_the_rows_the_mirror_has_not_synced_with_their_ids`) and the repository page's component tests (`TfRepo.kept.test.svelte.ts`).

- ADR-0032's *never in the database or on disk* is amended to *never in the mirror's tables; a page's reads are held in `sync.held_read`*. Its *Moving* and *Fixed* rules stand; *Live* now means *read every time by everything but a page*.
- A page can draw something older than the source for the time a read takes, or longer when the source is down, and says so. A write pressed from a held view is checked by the source when it lands, as every write is (ADR-0004); a refusal is told on the write.
- Migration `0073` adds `sync.held_read`: a new, empty table, nothing rewritten at the first start.
