Choices the mockup makes, for review

  1. Tabs regrouped. Two groups split by a thin rule: the repository at a ref (Files, Commits, Branches, Compare) and work in flight (Pull requests, Local changes). Compare becomes a tab of its own, since it now takes any base and any head, instead of lighting Pull requests.
  2. The landing is the Files tab with nothing open: the tree on the left, the last commit, then the README. No root listing beside the tree, since the tree is the listing.
  3. The tree persists across the Files tab: opening a file swaps only the right side. It has Go to file (T).
  4. The branch picker stays in the header at header height (#2238: a select in a button row takes the row's height).
  5. Renderer switcher is a small select in the file header, Render as …; its menu marks the default for the pattern and can change it. Pipeline is a bar under the file header: bytes → steps → renderer, with grips, inline arguments, remove, Add step and Save as default for the pattern.
  6. Side rail order: Ready to merge? (a checklist with a one-line verdict), Reviewers, Checks, Builds of the head, Conflicts, Local checkout. Merge… stays the header's primary and is disabled until the checklist is met.
  7. Diff toolbar sits sticky above the tree and files and holds the range picker, layout, Run pipelines, Ignore whitespace, where the diff was read from, and Viewed progress. Run pipelines and Ignore whitespace are pill toggles.
  8. Collapsed by default: lock and generated files, and files you marked viewed. A file over 1,500 changed lines shows Load diff in place of its lines.
  9. Waiting: a first read draws skeleton rows shaped like the tree, the commit line and the README; a re-read keeps the old content dimmed under a thin progress line at the top.
